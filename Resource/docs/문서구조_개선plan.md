## P1 — 스크립트

### ⑥ ★루트 `INDEX.md` 자동생성

```markdown
| 경로 | type | status | 한 줄 요약 |
```

★**Karpathy LLM Wiki 패턴의 핵심 기제**: *"LLM reads index.md first, identifies which articles are relevant, and loads only those."* 명시된 유효 스케일이 **~100~500 소스** — 209개인 우리는 정확히 그 구간.

⚠ 현재 허브는 **209개 중 36개(17%)**만 담고 있다.
★**반드시 frontmatter에서 스크립트 생성** — 손으로 쓰면 파일 하나 쓸 때마다 드리프트한다.

### ⑦ ★`§` 참조 586건 자동 변환

```
F7 §5-2                      (현재 — AI가 15개 파일에서 추측해야 함)
[[F7_스킬아키텍처_확정]] §5-2   ★권장
```
★**프로토타입 검증 완료**: 611건 중 **586건(95%)** 자동 변환 / **23건은 진짜 끊긴 참조**로 드러남.
★전문 앵커를 안 쓰는 이유: **헤딩 텍스트를 고치면 깨진다**(현재 25건 중 4건이 이미 그렇게 깨졌다).

나머지 3,225건은 **같은 파일 내 `§N`** — 우선순위 낮음.

### ⑧ 각 문서 첫 10줄에 결론 3줄
`Read`는 앞부분이 싸다. 현재 `스킬연출구조/plan.md`는 첫 헤딩이 `## Context`라 **결론을 보려면 451줄**을 읽어야 한다.

LLM 위키의 **1위 실패모드**가 *"낡은 것과 현재 것의 공존"*. 우리는 *"❌ 철회"*가 **산문으로만** 박혀 grep에 안 걸린다.

### ⑩ 허브 도달불가 27건 연결
대부분 완료 기능 → *"완료 아카이브"* 절 하나.

## 오너 뷰 층 — AI 정본의 파생물

★**파생물이면 "요약본과 본문이 어긋나는 사고"가 원리적으로 불가능하다.**
(그 사고는 이미 일어났다 — `전투완성/plan.md`의 `status` 첫 절 *"전 게이트 통과"* ↔ 본문 `- [ ] F4 미종결`)

```
docs/data/*_status.yaml   ← 상태의 유일 정본
        ├─→ <영역>_요약.md      (오너 어휘 + ★"눈으로 확인하는 법")
        └─→ 주제 문서 §결함·§잔여 (에이전트 어휘 + 차단자·담당)
```

**첫 대상 = 전투** (`전투_요약.md` ≤150줄):

| § | 내용 |
|---|---|
| §1 | 지금 한 판 (산문 3~5줄) |
| §2 | ★✅되는 것 / ❌안 되는 것 + ★**"눈으로 확인하는 법"** 컬럼 |
| §3 | ★오너가 해야 할 일 |
| §4 | 막혀 있는 것 |
| §5 | 전투 흐름 다이어그램 |

★**"눈으로 확인하는 법"이 요약본을 읽을거리에서 검증 도구로 바꾼다** — 오너는 문서를 믿는 게 아니라 확인하고 싶어 한다.
