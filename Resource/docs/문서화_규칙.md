# 📝 문서화 규칙 (Obsidian wiki)

> 모든 작업 산출물·중간 기록을 이 볼트에 남기는 규칙. Director와 전 에이전트가 준수한다.
> 관련: [[projectTP_허브]] · [[개발_워크플로우]]
#projectTP/규칙

---

## 1. 정리본 / raw 분리 (Karpathy RAG 방식)
- **정리본**: 기능 폴더 루트 `docs/features/<기능>/*.md` (청사진·plan·진행로그).
- **중간 산출물(raw)**: `docs/features/<기능>/raw/` — 에이전트 보고 원문, 게이트 결과, 중간 스크린샷.
- 정리본이 raw를 위키링크로 참조한다. raw는 버리지 않고 보존.

## 2. 중간 문서도 반드시 기록
- 단계 게이트 결과·TC 실행 결과·주요 결정 → 기능 폴더 `진행로그.md`에 **시간순 append**.
- 스크린샷은 `raw/`에 저장하고 `![[파일]]`로 임베드.
- "말로만 끝내지 않는다" — 실행 에이전트 보고도 요지를 진행로그에 남긴다.

## 3. 옵시디언 문법 적극 활용
- 위키링크 `[[노트]]` · `[[노트#헤딩]]` · 블록참조 `^id`.
- 계층 태그 `#projectTP/<기능>` (예: `#projectTP/기본전투무대`).
- frontmatter 필수: `type` / `feature`(기능문서) / `status` / `updated`.

## 4. 연결 원칙 (고아 노트 금지)
- 새 노트는 최소 1개 링크(허브 또는 상위 문서)로 연결한다.
- 기능 완료 시 [[projectTP_허브]] 문서목록/현재상태를 갱신한다.

## 5. 단순 유지
- 폴더 깊이 최대 3: `docs/features/<기능>/raw/`.
- 파일명 = 한글 명사형. 날짜는 frontmatter `updated:`에만(파일명에 날짜 금지).

## 6. 옵시디언 운용 (Obsidian)

> **핵심 원칙: 오너와 AI가 같은 규칙을 쓴다.** 오너가 옵시디언 UI에서 만든 노트와 AI가 Write 툴로 만든 노트가 구분되지 않아야 한다. 아래 규칙은 오너용 절차와 AI용 절차로 나눠 적지만, **같은 결과를 내기 위한 같은 규칙**이다.
>
> 볼트 루트 = `docs/`(`.obsidian`이 여기 있다). 개선(2026-08-13) 이후를 위한 절 — 정리한 다음 날부터 다시 어긋나지 않도록 유지 규칙을 못박는다.

### 6-1. GitHub 공개 제약 (가장 중요)

- 이 볼트(`docs/`)는 **공개 GitHub 저장소** `ProjectTP`(`D:\unreal\`) 안에 있다. **볼트에 넣는 것은 곧 공개된다.**
- 유료 구매 에셋 원본·재배포 금지 자산은 **볼트에 절대 넣지 않는다.** 압축 해제 위치는 반드시 `Resource\_RawAssets\`(비공개 LFS 저장소 `ProjectTP-Resource-Assets`) — `Resource` 직하나 `docs\`에 두면 공개로 올라간다.
- `.obsidian/` 중 `app.json` · `appearance.json` · `community-plugins.json` · `core-plugins.json` · `types.json` 5개만 git 추적 대상이다. `plugins/`(플러그인 코드)와 `workspace.json` · `cache`는 `.gitignore`로 제외돼 있다 — 각자 재설치.

### 6-2. 개행·표 정렬 노이즈 (원인 해결됨 — 재진단 불필요)

- **증상**: 옵시디언에서 열기만 한 `.md`가 내용 변경 없이 `git diff`에 `M`으로 뜬다(예: `전투로그.md` — `M`인데 diff는 0줄).
- **원인**: AI(Write 툴)는 LF로 쓰고 옵시디언은 CRLF로 저장 → 줄바꿈 문자만 달라지는 가짜 변경.
- **조치(2026-08-13, 완료)**: `D:\unreal\.gitattributes`에 `*.md text eol=lf` 신설. 적용 즉시 가짜 `M` 소멸. 다음 사람은 이 증상을 다시 진단할 필요 없다.
- **표 자동정렬**: 옵시디언은 표가 포함된 문서를 열기만 해도 셀 패딩을 재정렬해 `M`을 만들 수 있다(`_RawAssets_전수카탈로그.md`에서 실측 — 내용 동일, 패딩만 변경). 무해하지만 git diff 노이즈다. 커밋 전 `git diff`로 실제 내용 변경인지 패딩뿐인지 확인한다.

### 6-3. 새 노트 — frontmatter 필수 필드

**§3과 같은 규칙이다**(여기서 다시 적는 건 옵시디언 UI 생성 경로에도 똑같이 적용됨을 못박기 위해서다):

| 필드 | 적용 범위 | 실사용(2026-08-13 실측, 209개 기준) |
|---|---|---|
| `type` | 모든 노트 | 206 |
| `updated` | 모든 노트 | 193 |
| `status` | 상태가 있는 노트(계획·작업·검증) | 158 |
| `feature` | ★기능 폴더(`features/<기능>/`) 노트 | 154 |

- `tags`는 **선택**이다. 실사용이 **2개뿐**이라 필수로 올리지 않는다(계층 태그 `#projectTP/<기능>`는 §3 참조).
- `status`는 **enum 값만** 쓴다. enum 값 목록(`PASS`/`WIP`/`DRAFT`/`BLOCKED` 등)은 별도 확정 예정 — 확정 전까지 서술은 `status_note` 필드나 본문에 적고, `status` 필드 자체에 산문을 넣지 않는다.
- ⚠ **미결**: `project`가 **146개 문서**에서 쓰이는데 §3에도 여기에도 등재돼 있지 않다. 필수인지 관례인지 **frontmatter 정규화 단계에서 확정**한다 — 그 전까지는 기존 문서를 따라 쓴다.
- **오너**: 옵시디언 UI에서 노트 생성 시 위 필드를 채운다(편의 플러그인으로 템플릿을 써도 무방 — §6-9 참조).
- **AI**: `Write`로 새 노트를 만들 때 frontmatter에 위 필드를 직접 채운다.

### 6-4. 링크 — 동명 파일은 경로 링크 강제

- `plan.md`(10개) · `청사진.md`(8개) 등 동명 파일이 존재하는 이름은 **bare `[[plan]]` 금지** — 경로 링크로 쓴다: `[[features/전투완성/plan|plan]]`.
- bare 링크는 옵시디언에서 알파벳/사전 순 등 예측 불가한 대상으로 해석되며(현재 `[[plan]]` 94건이 전부 빈 `_TEMPLATE/plan.md`로 감), 오너와 AI 모두 같은 위험에 노출된다.

### 6-5. 앵커 — 헤딩 원문 그대로

- `[[노트#헤딩]]`은 헤딩 원문 **전체**가 필요하다. 옵시디언 앵커는 `*` `_` `~` `` ` `` `[` `]` 만 무시하고 마침표·괄호·슬래시는 그대로 유지해야 한다. 하나라도 빠지면 링크가 깨진다.
- 헤딩이 자주 바뀔 것 같거나 확신이 없으면 전문 앵커 대신 `[[파일]] §N` 형태를 쓴다(§N은 본문 텍스트이므로 헤딩이 바뀌어도 안 깨진다).

### 6-6. AI가 못 보는 것 — 사실은 반드시 평문에도

- 에이전트는 파일의 **평문 텍스트만** 읽는다. 옵시디언이 렌더링해서 보여주는 것 — **임베드(`![[...]]`) 결과 · dataview 쿼리 결과 · Bases 뷰 · 백링크 패널 · 그래프뷰 · 캔버스** — 는 AI에게 전부 보이지 않는다(빈 파일과 동일하다).
- 실물 확인: Obsidian CEO(kepano) 본인 볼트의 인덱스가 `![[Evergreen.base]]` 한 줄인데, AI에겐 빈 파일이다.
- **따라서 사실을 옵시디언 렌더링 산출물에만 두지 마라.** 임베드·dataview·Bases로 보여주더라도 같은 사실을 평문 본문(문장·표·목록)에도 반드시 적는다.

### 6-7. 폴더 — 새 기능은 `features/<기능>/`

- 새 기능 문서는 `docs/features/<기능>/`에 만든다. 루트에 새 md를 늘리지 않는다(루트는 이미 규약·카탈로그·계획이 섞인 진입점이다).

### 6-8. 이름 변경(리네임) — 옵시디언 UI 사용 후 vaultlint 1회

- 옵시디언 UI에서 노트를 리네임하면 `[[위키링크]]`는 자동 갱신된다. 그러나 **`§N` 형태의 텍스트 참조와 코드블록 안의 경로 문자열은 갱신되지 않는다.**
- 리네임 직후 반드시 vaultlint를 1회 실행해 깨진 참조가 없는지 확인한다.

### 6-9. 플러그인 — 오너 편의용 한정

- **에이전트는 옵시디언 플러그인을 실행할 수 없다.** 자동 인덱스 생성·정렬·변환 등 자동화는 반드시 `docs/scripts/`의 파이썬/노드 스크립트로 한다.
- 플러그인(Templater, Dataview 등)은 오너가 UI에서 쓰는 편의 도구에 한정한다 — 플러그인 산출물에 의존하는 규칙을 만들지 않는다(§6-6과 같은 이유).

### 6-10. 정리 주기 — 세션 종료 시 vaultlint

- 세션 종료 시 vaultlint를 1회 돌린다: `node docs/scripts/vaultlint/vaultlint.ts docs`.
- 실패(깨진 링크·깨진 앵커 등)가 이전보다 늘었으면 커밋 전에 고친다. `type` 32종·`status` 134종처럼 규칙 없이 며칠만 지나도 다시 어긋난다 — 이 절이 그 재발을 막기 위한 것이다.

## 기능 폴더 표준 구조
```
docs/features/<기능>/
├─ 청사진.md      ← 목표·범위·전제 (blueprint)
├─ plan.md        ← 단계·TC·진행 체크리스트 (plan)
├─ 진행로그.md     ← 게이트·결정·이슈 시간순 (log)
└─ raw/           ← 에이전트 원문·스크린샷·중간물
```
