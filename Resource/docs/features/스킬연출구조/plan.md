**→ 흡수 채택.** balance 우려는 실재하지만 **테이블 분리가 아니라 sentinel로 푸는 문제**다. 결정적 근거: 캐릭터 4필드 중 4번째만 다른 테이블 FK면 **카드 위젯·툴팁·조합 생성·중복 검출이 전부 테이블 분기**를 한다 = 오너 지시 3 위반.

**balance 우려는 3조건으로 봉인:**

| 조건 | 내용 |
|---|---|
| **C1** | 슬롯 축 = **`Layer`**(`BASIC`/`COMMON`/`JOB` + **`PASSIVE` 신규값 1개**). `Layer`는 `skills_30원자_초안.csv`에 **이미 있다** → 신규 축 0 |
| **C2** | `Category`(메뉴 탭 축)에 PASSIVE를 넣지 않는다 — 선택 불가한 것에 탭이 생긴다 |
| **C3** | **중립값 규약 + CSV 린트 강제**: `MotionRow = -1`(★**0 금지** — row0=Idle이라 idle 재생을 지시한다) · `Target=NONE` · `StagingId=0` · `FxCastId=FxImpactId=0` · `Cooldown=0` |

### 판정2 — 슬롯 조달은 `SkillIds` **밖**이다 (qa 실측이 유일하게 본 축)

qa 실측: `job_stats.csv`의 `SkillIds` = `31000000;31001000;33001000` — **전 6행 정확히 3토큰**. 소비처는 `SetActiveUnit`이 파싱해 `WBP_SkillMenu`의 **정적 Row 3개에 스탬프**한다.

| 시도 | 결과 |
|---|---|
| 4번째 토큰 추가 | 3행만 스탬프 → **패시브 무음 소실** |
| 메뉴 Row를 4개로 | 패시브가 **클릭 가능한 액티브로 노출** → `NotifySkillSelected(패시브)` → 공란 `Target`이 `PendingTargetToken`에 들어감 → 타겟 풀 0 → **소프트락**. (F7a ⑤ SELF 스킬 소프트락과 동형) |

**→ 확정**: 패시브는 **`SkillIds`에 넣지 않는다.** 별도 `PassiveId` 컬럼 + 메뉴 **3행 유지** + `NotifySkillSelected`에 **패시브 도달 시 거절 로그** 안전망.

이건 system-ui의 C2("메뉴는 3필드에서만 목록 생성")와 같은 결론이고, system-ui가 *"미확인"*으로 남긴 항목을 qa가 실측으로 채웠다.

### 판정3 — 패시브는 `ApplySkillEffects`를 **부르지 않는다** (qa Z1·Z2 방어)

qa가 정확히 짚은 2개의 지뢰:

| # | 지뢰 |
|---|---|
| **Z1** | Timing 순회 = **PRE/ON/POST 3개 `ForEach` + `EqualExactly` 필터**. `ON_TURN_START` 행을 넣으면 **세 필터 어디에도 안 걸려 조용히 폐기**된다. 에러 0·로그 0·컴파일 0 |
| **Z2** | `ApplySkillEffects` 최상위에 **쿨다운 세팅 + BattleLog 1줄**이 붙어 있다(F7 §8-6, 캐스트당 정확히 1줄). 턴마다 부르면 **로그 행수부터 SPD 오라클 diff FAIL** → F7b ⑦ 게이트 영구 통과 불가 |

**→ system-ui의 래퍼 추출안이 둘 다 방어한다.** qa는 이 안을 못 보고 "Timing 확장 금지"를 권고했지만, 정확한 답은 **호출 대상을 바꾸는 것**이다:

```
RunEffectBucket(Caster, SkillId, Timing, ContextTargets[])   ← 신규(현행 3-패스 버킷을 파라미터화 추출)
ApplySkillEffects(...) = 쿨다운·BattleLog + RunEffectBucket ×3   ← 얇은 래퍼로 축소
패시브       = RunEffectBucket(Owner, Owner.PassiveId, "ON_TURN_START", [Owner])
                 ↑ 쿨다운 세팅 없음 · BattleLog 방출 없음 → 오라클 diff 무영향
```

**+ Z1 방어 린트**: 알파 유효 `Timing` = `{PRE_HIT, ON_HIT, POST_HIT, ON_BATTLE_START, ON_TURN_START}`. **그 외 값은 임포트 FAIL**(무음 폐기 금지).

⚠ `RunEffectBucket` 추출 자체가 F7b 수술이다 → **⑦ 게이트 GREEN 이후 별도 커밋**(아래 순서 참조).

### 판정4 — 패시브 훅은 **알파 2종으로 봉인** (system-ui 7종 안 축소)

gameplay·qa가 독립적으로 같은 결론에 도달했다.

| 훅 | 구현 | 회귀 표면 |
|---|---|---|
| **`ON_BATTLE_START`**(=상시형) | 전투 시작 시 자신에게 **영구 STATUS 부여** 1회 → 이후 곱연산은 기존 `GetOutgoingAtkMult` 채널이 자동 처리 | **최소** — 검증된 `ApplyStatus` 재사용, 신규 코드 0 |
| **`ON_TURN_START`** | `EnterTurnStart` 말미(SKIP_TURN 판정 뒤)에 `RunEffectBucket` 1회 | **중간** — 신규 콜사이트 1개 |

**`ON_DAMAGED`/`ON_KILL`/`ON_DEATH`는 STUB 문서화만.** qa가 불변식 3개 동시 붕괴를 실증했다:

| 불변식 | 붕괴 |
|---|---|
| `bBattleOver`는 `ResolveHit` 내부에서만 세팅(H-5 레이스 차단) | ON_KILL 패시브 추가 데미지 → **`bBattleOver=true` 이후의 판정** |
| `bAlive` 선체크 = 시체 라이더 방지 | ON_DEATH 패시브는 **죽은 유닛이 발동 주체** — 가드와 정면 충돌 |
| `EnterTurnEnd` 단일 관문 | 동시 사망(A가 B를 죽이고 B의 ON_DEATH가 A를 죽임) → **양팀 전멸 승패 미정의** |

추가: `PendingSkillId` 단일 필드 오염(ON_DAMAGED는 캐스트 한복판) + 반사형 상호 재진입 무한재귀.

**★재귀 가드는 스코프를 줄여도 필수**: `PassiveReentryDepth ≤ 1`, 초과 시 로그 1줄 + 스킵(fail-closed).

### 판정5 — 영구 상태 어휘가 없다 (3개 에이전트 독립 확인)

`status_effects.csv` `DefaultDuration`은 정수이고 **무한/영구 어휘가 없다.** `TickStatusesAtTurnEnd`가 매 턴 차감 → **반드시 만료**한다.

**→ `DefaultDuration = -1`(영구 sentinel) 도입 + `TickStatusesAtTurnEnd`에 "-1은 차감 안 함" 1분기.** (gameplay가 제안한 "매우 큰 Duration" 우회는 매직넘버라 기각.)

### ★샘플링률 하락이 진짜 신규 요구사항

**83%(1000/1200) → 21%(1000/4800).** 83%일 땐 사실상 전수라 결과가 결정적이었는데, 21%가 되면 **생성 시드가 밸런스 변수**가 된다. 원자별 노출 빈도가 균일에서 확률적으로 바뀐다.

→ **필수 2건**: ① **생성 시드 고정 + 산출물에 기록** ② **블랙리스트 훅**(금지 조합)

②는 대가가 아니라 **이득**이다 — 여유 4.8배가 곧 **거부 샘플링 여지**다. 극단 OP 조합을 빼고 다시 뽑을 수 있다. 여유 20%에선 불가능했던 레버다.

⚠ **유일성 키 확장**: `(포지션,평타,공용,직업)` → 패시브 추가 필요(§7-3 중복 재배치 스크립트 영향).

## ★패시브의 진짜 위험 — 카운터할 수 없는 유일한 층

기존 카운터 삼각(막기·STUN·ATK_DOWN)은 **전부 "행동을 무는" 카운터**다. 셋 다 패시브엔 안 통한다 — STUN에 걸린 유닛의 패시브도 계속 돈다. ★**단 2026-08-11 Director 판정으로 부분 완화**: 이 서술은 **상시형(`ON_BATTLE_START`)에 한해서만 참**이다. `ON_TURN_START` 패시브는 **STUN 시 미발동**으로 확정됐다([[D1_4슬롯구조_확정]] §7-2) — 행동성 훅은 행동 카운터가 물어야 하고, 패시브에 카운터가 하나라도 생기는 것은 순이득이다. 액티브 3층은 쿨다운·코스트·카운터가 걸리는데 **패시브만 코스트 0·상시·무적**. **가위바위보 대칭이 이 층에서만 깨진다.**

**balance와 qa가 독립 산출로 수렴했다:**

| 패시브 OUT_MULT | 유효 데미지 | vs 딜 Hp 84 |
|---|---|---|
| 없음 | 72 | 마진 12 ✓ |
| +0.10 | 80 | 마진 4 ⚠ |
| **+0.15** | 83 | **마진 1** ⚠ |
| **+0.20** | 87 | **선공 원킬 — 무원킬 게이트 붕괴** |

balance의 독립 유도(*"+7% 보수 / +15% 절대, +16%면 1턴 원킬"*)와 **같은 지점을 가리킨다.**

| 항목 | 상한 |
|---|---|
| 상시 Atk | **+7%**(보수) / +15%(절대) |
| 상시 Def | **+3** — ★칩락 실마진은 문서상 16이 아니라 **8**이다(ATK_DOWN ×0.75가 부등식 밖에 있었다: `floor(29×0.75) − 13 = 8`) |

**좋은 소식**: V2 콤보(ATK_UP+파이어볼)에 +8% 패시브를 얹어도 **막기 하드카운터는 살아있다**(99 → 막기 시 49 < 84 생존). 상성 B 무손상.
**나쁜 소식**: `ATK_UP + 패시브 +0.20`이면 `Π(1+V)=1.50` → **111 데미지**. 곱 채널이라 콤보와 곱해진다.

**스탯 조정은 "가산"이 아니라 "이전":**
```
✗ 가산: 탱 Def 11 + 패시브 +3 = 14   → §7 전면 재검산, 마진 8→5
```

## ★하드코딩 판별 기준 (qa 산출 — D1이 설계 문서에 그대로 박을 것)

## 연출·이펙트 설계 (system-ui 산출 + gameplay·qa 실측 보정)

**2층 구조** — `motions.csv`가 검증한 "스킬은 참조만, 파라미터는 대상 테이블이 편다" 패턴 복제:

"3종으로 충분"은 **현행 5스킬 기준**이었다. 5스킬이 커버하는 축은 근접 ENEMY1 / SELF / ALLY1뿐이다. 30원자를 대조하면 **3개 축이 표현 불가**:

### ★`AdvanceRatio` 소비 계약을 명문화하라

float 타입 유지는 **정당**하다(bool 전환 비용 = struct 편집 + DT 재임포트 vs 유지 비용 0, 비대칭이 명확). 결함은 타입이 아니라 **계약 부재**다 — *"런타임은 `AdvanceRatio > 0`만 읽는다"*면 balance가 `0.9`를 적어도 **아무 일도 안 일어나는 무음 실패**다(F7 §8-4 fail-closed 위배).

**D1이 택1 명문화**: (a) 런타임이 **실제 Lerp 알파로 소비**(중간값 유효 — 근접 정지 거리 = 현재 매직넘버 "거리임계 1.0"의 데이터화 자리) 또는 (b) **`{0,1}만 유효` + 임포트 검증룰**(그 외 FAIL).

**명명 [Low]**: "Advance(전진)"는 아군 힐(뒤쪽으로 이동)엔 모호. **"캐스터→타겟 벡터의 보간 비율"**로 정의하면 SELF가 벡터 0으로 자동 제자리가 되어 프로필 1종이 자연 절약된다.
