### 1-2. `0.45`/`0.55`의 정체 — 그래프 실측 (`BP_BattleSpawnPoint` EventGraph)

`PlayAttack` 커스텀 이벤트(잔상 Smear 트리거) 체인:

```
IsAttackFamily(모션) == TRUE
  → SetMaterial(EffectQuad, SmearMID)
  → SetVisibility(EffectQuad, TRUE)
  → RetriggerableDelay(Duration = 0.45)   ← 실측 리터럴
  → SetVisibility(EffectQuad, FALSE)
```

`PlayHurtReaction` 커스텀 이벤트(HitMID) 체인(생존/사망 두 분기 모두 동일 패턴):

```
SetMaterial(EffectQuad, HitMID)
  → SetVisibility(EffectQuad, TRUE)
  → RetriggerableDelay(Duration = 0.55)   ← 실측 리터럴
  → SetVisibility(EffectQuad, FALSE)
```

→ **`0.45`/`0.55`는 "지연 시간"이 아니라 "이펙트 표시 지속시간"이다.** `SetVisibility(true)`와 `(false)` 사이 간격이 곧 화면에 보이는 시간이므로, 기능상 "재생 시간"으로 취급하는 것이 맞다.

**★함정 발견 — 같은 그래프에 `0.45`가 하나 더 있다.** `K2Node_CallFunction_28`(`Duration=0.45`)는 **SpriteMID(캐릭터 본체 스프라이트)를 Hurt→Idle로 되돌리는 타이머**로, VFX와 무관한 리터럴이 우연히 같은 값일 뿐이다. 이걸 legacy 행에 잘못 옮기면 안 되는 게 실제로 검증해야 했던 함정이었다(과제 지시의 "판별하라"가 가리킨 게 바로 이것).

### 1-3. FPS는 역산이 아니라 이중 확정

같은 그래프의 **다른 노드**(`K2Node_PromotableOperator_19`, 캐릭터 모션 딜레이 계산용)가 정확히 `PendingFrameCount / 8.0 − 0.05` 식을 쓰고 있다 — 이 프로젝트에 이미 **"프레임수/FPS − 0.05 세이프마진"** 패턴이 실재한다는 뜻이다. 이 식에 FPS=10을 대입하면:

- Smear: `5 / 10 − 0.05 = 0.45` ✅ 리터럴과 정확히 일치
- Hit: `6 / 10 − 0.05 = 0.55` ✅ 리터럴과 정확히 일치

→ **MI의 `FPS=10` 직접 조회값과 "역산식이 요구하는 FPS=10"이 독립적으로 일치**한다. 추측이 아니라 이중 실증이다.

## 2. Q4 — `HitMID` 재생 스킬 범위

### 2-1. 실측 경로 (`BP_BattleManager` EventGraph, MCP `find_nodes`/`get_node_infos`)

`PlayHurtReaction`(HitMID 트리거) 호출은 **EventGraph에 정확히 1곳**뿐이며, 다음 게이트를 통과해야 실행된다:

```
ResolveHit(Attacker, Target, SkillId) 실행 후
  → DT_Skills에서 SkillId 행을 다시 조회(BreakFSkillsRow)
  → EqualExactly(Target필드, "ENEMY1")
      TRUE  → Target->PlayHurtReaction()  (HitMID 재생)
      FALSE → (아무 것도 안 함)
```

`skills.Target`(문자열 필드, `PrimaryTargetGroup`이 아니라 **`Target`**)이 정확히 `"ENEMY1"`일 때만 켜지는 **단일 게이트**다. `HitMID` 화이트리스트나 스킬별 개별 분기는 존재하지 않는다.

### 2-3. D1 §3-6 표와 대조 — **1건 불일치**

| §3-6 행 | 원자 | 설계 `FxImpactId` | 실측 게이트 결과 | 판정 |
|---|---|---|---|---|
| row6 SELF | 막기 | `0`(없음) | 미재생 | ✅ **일치** |

**설명**: D1 §3-6은 이미 "이 표는 설계 배정이지 실측이 아니다"라고 스스로 경고했고(2차 개정 각주), 그 경고가 실제로 맞았다. 치유(ALLY 대상) 스킬에 임팩트 FX를 달려는 D1의 설계 의도는, 현재 런타임의 `Target=="ENEMY1"` 하드코딩 게이트 아래서는 **절대 발동하지 않는다.** `vfx.csv`에 치유용 임팩트 Id를 등록하는 것 자체는 문제없지만(§3 표에 반영), **그 Id가 실제로 화면에 뜨려면 게이트 조건을 `Target != "SELF"`류로 넓히는 별도의 gameplay 작업(D6 범위)이 필요**하다. 본 문서는 이 사실을 기록만 하고 코드를 고치지 않는다(uasset 무접촉 제약).

## 5. 선별에서 뺀 것과 이유 (빠뜨림이 아니라 뺐음)

1. **180장 중 175장 미등재.** D1 §3-6이 요구하는 롤은 캐스트(공격/지원)·투사·임팩트 3역할뿐이고, 최소집합 원칙상 역할당 1~2행이면 충분. 나머지는 재고에 남아 있고(`vfx_inventory_raw.csv`가 조인 키 보유) 필요해지면 1행 추가 비용으로 등록 가능.
2. **임팩트 신규 아틀라스 0행.** `legacy_hit`(`63000200`) 하나로 `FxImpactId>0` 26원자 전량을 커버했다. 근거: (a) 지금도 라이브 5스킬이 전부 이 하나만 쓴다 — 무회귀 원칙과 정확히 부합 (b) `skills.csv`에 아직 속성(화염/빙결 등) 컬럼이 없어 임팩트를 분화할 데이터 근거 자체가 없다 (c) 최소집합 원칙.
3. **캐스트 FX를 공격/지원 2종으로만 단순화.** 지원-SELF(방어형: 막기·방어태세·수호방벽·기력모으기)와 지원-ALLY(회복형: 치유·응급치유·축복)를 시각적으로 더 나눌 수도 있었으나, 둘 다 `stg_support_cast` 프로필 하나(제자리 캐스트)를 공유하고 `skills.csv`에 방어/회복 구분 축이 없어 1행(`63000400`)으로 통합했다. 베타에서 세분화가 필요해지면 art-pipeline 재작업이 아니라 **balance가 CSV 1행을 복제(TexPath 재사용, ColorRow만 변경)**하면 된다.
4. **처형·반격참 등 JOB급 근접기 전용 강조 캐스트 미생성.** D1 §3-6 실증표가 근접·도약 15원자 전량을 `FxCastId=0`(모션폴백)으로 이미 확정했다. "필살기다운 강조"가 필요한지는 데이터 행 부재 문제가 아니라 **미정 디자인 정책**이라 알파 범위 밖으로 뺐다.
5. **`ColorRow` 1~5 변형 미등재.** 신규 3행 전부 `ColorRow=0`(적주황, 180장 전수 100% 안전 계열)만 등록했다. 원소별 색 변형(예: 빙결=row2 계열)이 필요해지면 `TexPath`/`GridX`/`FrameCount`는 이미 알려져 있으므로 **balance가 손으로 CSV 행을 복제**할 수 있는 수준이다.
6. **`ColorRow` 6~8 미사용.** D1이 이미 "파일별 색 계열 불일치 89~96%"로 예약 처리(L25 린트 강제 대상)했으므로 본 문서도 손대지 않았다.
