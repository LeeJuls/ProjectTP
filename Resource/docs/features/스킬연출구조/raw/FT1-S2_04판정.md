## 3. Part A — 채택안: `session.py` 세그먼트 순방향 귀속 (구체 변경 지점)

### 3-1. 변경 파일 = `docs/scripts/battle_log/session.py` 1파일, 함수 = `assign_sessions` 1개

`assign_session_keys`·`derive_sid`·`parser.py`·`tokens.py`·`oracle.py`는 **무변경**(소비자 전수 grep: `assign_sessions` 소비자는 selftest뿐, oracle.py는 아직 미소비).

**계약(신규 문구 — 전투로그.md §2-1에 그대로 옮긴다)**:
> 세그먼트 = 엔진 `up for play` 라인에서 다음 `up for play` 라인까지(= `AU-F0a-01`이 이미 쓰는 구간 정의를 파서에 승격). 세그먼트의 sid = 그 세그먼트 안 **첫 `SessionBoundary|` 마커의 프리픽스 ts**이며, 마커 이전 선두부(BeginPlay 경합 구간)도 **소급하여 그 sid에 귀속**한다. 마커가 없는 세그먼트는 전체 None(직전 세션에 병합 금지 — `AU-F0a-05` 계승). `init_ordinal`의 의미는 불변("INIT 카운트")이나, ★마커 라인 자신은 발화 순서에 따라 ordinal 0 또는 1에 앉을 수 있다 — 마커의 역할은 sid 공급뿐, ordinal 판정에 쓰지 않는다.

**앵커 검출**: 모듈 상수로 raw 라인 substring 2중 매치 — `"]LogWorld: Bringing World "` ∧ `" up for play ("`. 실측 원문(L17289):
```
[2026.08.13-03.11.56:600][326]LogWorld: Bringing World /Game/Stages/UEDPIE_0_map_battle_octopath.map_battle_octopath up for play (max tick rate 3) at 2026.08.13-12.11.56
```
★이 리터럴은 BP PrintString 토큰이 아니라 **엔진 발화 라인**이므로 tokens.py(게이트③: BP 토큰 프리픽스의 SSOT)에 넣지 않는다 — `session.py` 모듈 상수 + 이 사유 주석으로 둔다.

**참조 구현(의사코드 — 실행자는 이 구조를 유지하되 네이밍·주석은 모듈 관례를 따를 것)**:

```python
_WORLD_UP_FOR_PLAY = (" up for play (", "]LogWorld: Bringing World ")  # 엔진 앵커 — tokens.py 밖(게이트③ 범위 아님)

def assign_sessions(raw_lines):
    boundary_prefix = _session_boundary_prefix()
    out = []
    current_sid = None
    pending = None            # None = 버퍼링 비활성 / list = up for play 이후 마커 대기 중
    for raw in raw_lines:
        if all(m in raw for m in _WORLD_UP_FOR_PLAY):
            if pending is not None:                    # 직전 세그먼트가 마커 없이 끝남
                out.extend((None, r) for r in pending) # → None (bleed 금지, F0a-05 계승)
            pending = [raw]                            # 새 세그먼트 개시
            current_sid = None                         # ★직전 sid 전파 차단 지점
            continue
        meta = parser.parse_line_meta(raw)
        if meta is not None:
            ts, _frame, content = meta
            if content.startswith(boundary_prefix):
                current_sid = derive_sid(ts)
                if pending is not None:                # ★세그먼트 선두부 소급 귀속
                    out.extend((current_sid, r) for r in pending)
                    pending = None
                out.append((current_sid, raw))
                continue
        (pending.append(raw) if pending is not None else out.append((current_sid, raw)))
    if pending is not None:                            # EOF까지 마커 없음 — fail-safe
        out.extend((None, r) for r in pending)
    return out
```

### 3-2. 검증 성질 (재검증이 이것들을 확인한다)

1. ★**하위호환 100%**: `up for play` 라인이 없는 입력에서는 첫 분기가 한 번도 발화하지 않아 **현행과 출력이 동일**하다 → 기존 selftest 36케이스(합성 픽스처엔 엔진 라인 없음)는 **무수정 전량 PASS**여야 한다. 1건이라도 깨지면 구현 오류다.
2. **순서 불변성**: 마커가 INIT보다 앞서든 뒤서든 첫 전투 원장은 `(sid, 1)` — 마커 선행이면 (마커=0, INIT→1), 마커 후행이면 (선두부 소급 귀속, INIT→1, 마커도 1). ★기존 합성 케이스(PM지시④, 마커 선행 가정 `[0,0,1,1,2,2]`)와 신규 실측 케이스(마커 후행)가 **둘 다 이 성질의 증인**이 된다.
3. **fail-loud 유지**: 마커 발화가 실패한 세그먼트(BP 파손 등)는 전체 None → 원장이 남의 sid에 붙는 경로가 없다.
4. 메모리: pending은 최대 1 세그먼트(수백 줄) — 무해.

## 4. 기각한 안과 이유

### 4-A. 파서 "보조 None-경계"만 (착수판정 §7-미확인#3의 원래 후보 — ★절반 기각)

`up for play`에서 sid를 None으로 끊기만 하면 bleed는 막지만: ⓐ 세션 N의 초기화 26줄이 **자기 세션에도 귀속되지 못하고** 파일 선두 잡음과 같은 None 무리에 섞인다(`AU-F0x-02`류 세션 단위 FLOW 판정 불능 지속) ⓑ 첫 전투가 여전히 `(sid, 0)`에 앉아 계약 문구("0=예비")와 모순 — 오라클이 특례를 안고 가야 한다. **순방향 귀속(§3)은 같은 앵커로 두 문제를 다 닫고 구현 증분이 버퍼 하나뿐**이라 상위호환이다. None-경계의 fail-safe 성질(마커 없는 세그먼트 → None)은 §3에 그대로 포함됐다.

### 4-B. 마커를 더 이르게 (기각 — 결정적)

**BP additive 수술로 "마커 이전 0줄"은 달성 불가능하다.** 첫 BPUM 발화자는 SpawnPoint BeginPlay이고(실측 L17294), 어떤 액터에 심어도 타 액터 BeginPlay와의 경합이며 그 순서를 엔진이 계약하지 않는다. 변형 전수 검토: ⓐ GameMode BP — 이 레벨은 `Game class is 'GameModeBase'`(엔진 기본, L17387 실측)라 **신규 BP 제작+레벨 지정 = `.umap` 수정**, S2의 ".umap 무변" 규율 위반 + 신규 수술 대상 ⓑ Level BP — 신규 수술 대상 + 순서 여전히 비보장 ⓒ `InitBattle` 선두 — RESTART마다 재발화해 `AU-F0a-01`("구간당 정확히 1줄") 파괴 ⓓ `RegisterUnitReady` 첫 호출 — "첫 호출" 판별용 상태 변수 신설 필요 = additive 규율 위반, 그리고 그래도 앞의 VFXSetup(같은 SpawnPoint BeginPlay 선행분)을 못 이긴다 ⓔ ConstructionScript — 에디터 로드·이동마다 발화(로그 오염). **전 변형이 목적 미달이거나 규율 위반.** 무엇보다 파서가 로그를 전량 후처리하는 이 구조에서 순서 문제는 파서 좌표계가 흡수하는 것이 옳고, 그게 §3이다.

### 4-C. TC 재정의 (기각)

불필요 — `AU-F0a-04` 원문이 이미 "≥1줄 → 계약 요구" 경로를 갖는다(§0-1). "기준을 0줄에서 완화"하는 재정의는 원문 오독 위에 서고, 계약 보강 없이 게이트만 닫으면 §1-2의 실해가 방치된다. ★단 원문의 예시 처리("UNKNOWN 귀속 / fail-loud")보다 §3(자기 sid 소급 귀속 + 마커 부재 시 None)이 강한 처리임을 Part C에서 TC에 주석으로 남긴다 — 조용한 강화도 드리프트다.
