## 1. ① `PassiveId = NONE` 어휘 + 4슬롯 계약

### 1-1. 어휘 정의 (정식)

| 항목 | 확정 |
|---|---|
| 컬럼명 | **`PassiveId`** ([[네이밍_폴더_규약]] §4-A 외래키 규칙 `<대상단수>Id` 준수) |
| 타입 | **int32** (FK → `skills.csv`, `Layer==PASSIVE` 행) |
| **NONE 값** | **정수 `0`** |
| CSV 셀 표기 | **`0` 명시. 공란 금지 — 린트 L07a FAIL** |
| 사람용 표기 | 문서·`Memo`·`#id_txt`에서는 `NONE`으로 쓴다 |

> **왜 공란이 아니라 명시적 `0`인가**: DT int 임포트는 공란을 **0으로 강제 캐스팅**한다. 즉 저장값은 같지만 *"패시브가 없다"*와 *"아직 안 채웠다"*가 **CSV 위에서 구별 불가**해진다. A2가 1000행을 굽는 순간 이 구별이 사라지면 미기입 버그가 무음으로 통과한다. 명시 `0` + 공란 FAIL 린트가 그 구별을 데이터 위에 남긴다.
> **왜 `-1`이 아닌가**: `-1`은 plan 판정1-C3에서 **`MotionRow`의 중립 sentinel**로 이미 쓰인다. FK 컬럼의 "참조 없음"은 `StagingId=0`·`FxCastId=0`과 동일하게 `0`이어야 어휘가 하나로 유지된다(`0` = "가리키는 행 없음", `-1` = "이 축을 쓰지 않음").

### 1-2. 4슬롯 계약 (★Z5의 답)

```
캐릭터 1행 = [ 평타 1 ] [ 공용 1 ] [ 직업 1 ]   +   [ 패시브 0..1 ]
             └────── SkillIds (3토큰, 필수) ──┘       └ PassiveId (int, 0 허용) ┘
                     "항상 3"                            "0 또는 1"
```

> ★**4슬롯은 "항상 채워지는 4"가 아니다.** 정식 명칭 = **"3 필수 + 1 선택"**. `PassiveId = 0`(NONE)은 **결함이 아니라 유효한 정상 상태**이며, 알파 테스트 8기·회귀 기준선·기존 6개 `job_stats` 행이 전부 이 상태다.

### 1-3. P-NONE 불변식 (원장 봉인의 근거)

`PassiveId == 0`인 유닛에 대해 런타임이 보장하는 것:

| # | 불변식 |
|---|---|
| **PN-1** | `RunEffectBucket(...)` 호출 **0회** (`ON_BATTLE_START`·`ON_TURN_START` 양쪽 모두) |
| **PN-2** | `PassiveLog\|` 방출 **0줄** |
| **PN-3** | `BattleLog\|` 행수·필드 **완전 불변** (plan Z2 방어) |
| **PN-4** | `ActiveStatuses` 배열 변동 **0** · `bBlockActive`/`BlockValue` 변동 **0** |
| **PN-5** | 턴 길이(연출 시간) 변동 **0** → MA-1 재생 원장 무영향 |

**게이트**: 8기 전원 `PassiveId=0`으로 [[SPD원장_오라클_v1]] §7 20행 재실행 → **행 단위 diff 0**. (H2 규칙 준수: 요약값 일치는 PASS 근거 아님.)

### 1-4. SPD 오라클 §0 갱신 (본 문서에서 실행 완료)

`docs/features/전투완성/raw/SPD원장_오라클_v1.md` §0 고정입력 표에 **행 1개 추가**:

| 항목 | 값 | 근거 |
|---|---|---|
| **패시브 슬롯** | **없음 — 8기 전원 `PassiveId = 0`(NONE)** | 본 문서 §1 |

- **수치·기존 행·§4 본표·§7 파싱 CSV는 무접촉.** 추가된 것은 §0 표의 1행 + 각주 1줄뿐이다.
- 목적: *"원장이 어떤 전제 위에 봉인됐는지"* 를 명시. 이후 누군가 8기에 패시브를 붙이면 **§0이 바뀌었으므로 전면 재유도**가 그 문서 자신의 규칙(`바뀌면 전면 재유도`)으로 강제된다.

## 2. ② 슬롯 조달 SSOT (plan L2 해소)

### 2-1. 판정

| 후보 | 판정 | 사유 |
|---|---|---|
| `job_stats.SkillIds`(라이브, 6행 3토큰) | **현 SSOT — 유지·확장** | 라이브 소비 경로가 이미 여기를 판다. 여기 말고 다른 곳에 슬롯을 두면 **이중 진실** |
| `characters.csv`(미존재) | **A2 이후 SSOT — 동일 스키마 승계** | 청사진의 1000행. 아직 파일 없음 → **본 문서는 스키마 계약만 확정, 파일 생성은 A2** |
| `position_stats.csv`(balance v1 예고) | **슬롯 미보유 — 스탯 전용** | ★결정적: 포지션은 **3행**이다. 슬롯을 포지션이 소유하면 1000캐릭터가 **3종류로 붕괴**한다. 포지션은 *"어떤 풀에서 뽑는가"*(게이팅)만 소유하고, *"무엇을 뽑았는가"*(인스턴스)는 유닛 행이 소유한다 |

> **확정 규칙 (한 줄)**: **슬롯은 "유닛 1행 = 캐릭터 1명"인 테이블만 소유한다.** 지금은 `job_stats.csv`, A2 이후 `characters.csv`. 두 테이블은 **동일한 2컬럼 계약**을 만족하므로 소비 코드는 조회 대상 DT만 바뀌고 파싱 로직은 무변경이다.

### 2-2. 슬롯 2컬럼 계약 (양 테이블 공통 — A2가 그대로 복사)

| 컬럼 | 타입 | 규칙 |
|---|---|---|
| `SkillIds` | String | `;` 구분 **정확히 3토큰**. 순서 고정 = **`평타 ; 공용 ; 직업`** → `WBP_SkillMenu` Row 1/2/3 스탬프 순서와 1:1. 공란·2토큰·4토큰 전부 린트 FAIL |
| **`PassiveId`** | int32 | `0` = NONE. `!=0`이면 `skills.csv`에 존재 ∧ `Layer==PASSIVE` ∧ `PositionTag ∈ {행 포지션, UNIVERSAL}` |

**즉시 반영 (D6, 라이브)**: `job_stats.csv`에 `PassiveId` 컬럼 1개 추가, **6행 전부 `0`**. → §1-3 PN-1~5로 원장 무영향.

### 2-3. A2 조달 경로 (1000행 생성기가 무엇을 하는가)

```
positions.csv(3) ─┐
grades.csv(N) ────┤
                  ├─▶ [A2 생성기, 시드 고정] ─▶ characters.csv (1000행)
skills.csv ───────┘                              ├ PositionId, GradeId
  ├ Layer=BASIC   (10, PositionTag=SHARED)        ├ SkillIds  = "<평타>;<공용>;<직업>"
  ├ Layer=COMMON  (10, PositionTag=SHARED)        └ PassiveId = <패시브 Id> 또는 0
  ├ Layer=JOB     (10, PositionTag별 게이팅)
  └ Layer=PASSIVE (10, PositionTag별 게이팅)      ※ Layer=PROBE는 풀에서 제외(§5-3)
```

| 단계 | 규칙 |
|---|---|
| 풀 구성 | 평타 = `Layer==BASIC` 전체(10) / 공용 = `Layer==COMMON` 전체(10) / 직업 = `Layer==JOB ∧ (PositionTag==행포지션 ∨ UNIVERSAL)`(4) / **패시브 = `Layer==PASSIVE ∧ (PositionTag==행포지션 ∨ UNIVERSAL)`(4)** |
| 추첨 | 4축 독립 추첨. **시드 고정 + 산출물 헤더에 시드 기록**(plan §샘플링률) |
| 유일성 키 | **`(PositionId, 평타, 공용, 직업, PassiveId)`** — ★패시브 추가로 키가 4→5원소로 확장됨. 기존 중복 재배치 스크립트 수정 필요 |
| 블랙리스트 훅 | `(직업, 패시브)` 페어 금지 목록 파일 1개. 뽑힌 조합이 목록에 있으면 **재추첨**(거부 샘플링). 알파 = 빈 목록 |
| 직렬화 | `SkillIds` = 3토큰 `;` 조인. **패시브를 절대 조인하지 않는다**(판정2) |

> **알파 스코프 주의**: 패시브 풀이 D5에서 비어 있으면(행 0) 생성기는 **전 행 `PassiveId=0`**을 쓴다 — 이것이 정상 동작이며 fallback이 아니다(§1-2).

### 2-4. 안전망 — `NotifySkillSelected(패시브ID)` 거절 (판정2 요구)

**삽입 위치**: `NotifySkillSelected`의 **최상위 첫 가드**(기존 쿨다운 가드보다 **앞**). 뒤에 두면 쿨다운 조회가 공란 데이터에 먼저 닿는다.

```
NotifySkillSelected(SkillId):
  row = DT_Skills[SkillId]
  if (!row.Found)                → Reject("SKILL_ROW_NOT_FOUND")   ; return
  if (row.Layer == "PASSIVE")    → Reject("PASSIVE_NOT_SELECTABLE"); return
  if (row.Layer == "PROBE" && !bDebugProbesEnabled)
                                 → Reject("PROBE_NOT_SELECTABLE")  ; return
  … 기존 경로(쿨다운 가드 → PendingSkillId 세팅 → 상태 전이) …

Reject(reason):
  Log("PassiveLog| reject skill={SkillId} reason={reason} unit={ActiveUnitSlot} turn={T}")
  return   ← 부작용 0
```

**"상태 무변"의 정확한 정의 (검증 가능한 형태)** — 거절 경로 통과 후 다음이 **전부** 성립해야 한다:

| # | 불변식 |
|---|---|
| RG-1 | `PendingSkillId` **미변경** |
| RG-2 | `PendingTargetToken` **미변경**(공란 `Target`이 타겟 풀 0을 만드는 F7a ⑤형 소프트락 차단) |
| RG-3 | `SelectedTargets[]` **미변경** |
| RG-4 | 전투 상태머신 전이 **0회** (`AWAIT_COMMAND` 유지) |
| RG-5 | `BattleLog\|` 방출 **0줄** (오라클 diff 무영향) |
| RG-6 | `PassiveLog\|` **정확히 1줄** |
| RG-7 | 위젯 `bSelected` 하이라이트 변동 **0** |

**상태 전이표 (`AWAIT_COMMAND` 진입 입력 전량)**

| 입력 | 조건 | 전이 | 부작용 |
|---|---|---|---|
| `NotifySkillSelected(S)` | 행 미발견 | **없음** | `PassiveLog\|` reject `SKILL_ROW_NOT_FOUND` |
| `NotifySkillSelected(S)` | `Layer==PASSIVE` | **없음** | `PassiveLog\|` reject `PASSIVE_NOT_SELECTABLE` |
| `NotifySkillSelected(S)` | `Layer==PROBE` ∧ 디버그 off | **없음** | `PassiveLog\|` reject `PROBE_NOT_SELECTABLE` |
| `NotifySkillSelected(S)` | 쿨다운 중 | **없음** | 기존 경로 유지 |
| `NotifySkillSelected(S)` | `Target ∈ {SELF, ALLY1}` 등 자동 해결 | → `EXECUTING` | `PendingSkillId=S` |
| `NotifySkillSelected(S)` | `Target` 수동 지정 필요 | → `AWAIT_TARGET` | `PendingSkillId=S`, `PendingTargetToken=row.Target` |

**게이트 TC(qa D3 인계)**: 라이브에서 `NotifySkillSelected(35000000)`을 강제 호출 → RG-1~7 전량 확인 + **소프트락 0**(다음 입력이 정상 수락되는지까지).

## 3. ③ 연출 프로필 — 4행으로 6축을 덮는다

## 4. ④ `AdvanceRatio` 소비 계약 — **(a) 실제 Lerp 알파** 확정

### 4-1. 판정

**(a) 채택.** (b) `{0,1}만 유효`는 기각.

| 기각 사유 (b) | |
|---|---|
| 1 | float 타입에 2값만 허용하면 **타입과 계약이 어긋난 채 영구 고착**된다. bool로 갈 거면 지금 bool이어야 하는데, plan이 이미 float 유지를 정당화했다 |
| 2 | **근접 정지 거리가 데이터가 될 자리를 영구히 잃는다.** 근접·도약이 타겟에 얼마나 붙느냐는 30원자에서 실제로 다를 수 있는 값이고, 지금 봉인하면 나중에 새 컬럼이 생긴다(= 축 추가) |
| 3 | 도약 프로필은 "완전히 붙지 않고 조금 앞에 착지"가 자연스럽다 — `{0,1}`로는 표현 불가 |

### 4-2. 정의 (명문 — 이 문장이 계약이다)

> **`AdvanceRatio` = 캐스터 현재 위치 → `ResolveApproachAnchor(Caster, PrimaryTarget)` 로 향하는 벡터의 보간 알파.**
> 접근 목표 위치 `P = Lerp(Caster.Loc, Anchor.Loc, AdvanceRatio)`.

```
ResolveApproachAnchor(Caster, PrimaryTarget):
  if (PrimaryTarget == Caster)                 return Caster.Loc          # SELF → 벡터 0 → 자동 제자리
  if (AttackPointOverride is valid)            return AttackPointOverride # N6 경로 그대로 존치
  if (AttackPoint_<Caster.Team> exists)        return AttackPoint.Loc     # 현행 동작 = AdvanceRatio 1.0
  return PrimaryTarget.Loc                                                # 최종 폴백
```

| 성질 | 결과 |
|---|---|
| **회귀 0** | 근접 프로필 `AdvanceRatio = 1.0` → 종점이 현행 `AttackPoint_<team>`과 **동일** → 라이브 5스킬 이동 거리·시간 **무변** |
| **SELF 자동 처리** | 벡터가 0이라 알파와 무관하게 제자리. plan이 예고한 *"프로필 1종 자연 절약"* 실현 |
| **fail-loud** | `0.9`를 적으면 **실제로 90%만 이동한다.** 무음 실패가 구조적으로 불가능 |
| **N6 방어 유지** | `AttackPointOverride` Clear 계약(`then` **AND** `RowNotFound` 양 경로)은 **무변경 존치**. 실패 시 *"다음 턴 파이어볼이 아군에게 걸어간다"* 무음 버그가 오라클 diff 0을 통과하므로, `StagingId` 조회 재배선 후 **Clear 지배 재확인이 D6 게이트 항목** |
| 복귀(WalkBack) | `AdvanceRatio == 0` → 접근·복귀 **양쪽 모두 스킵**(비대칭 금지 — 접근만 스킵하고 복귀를 남기면 캐스터가 뒤로 밀린다) |

### 4-3. 임포트 검증 (fail-closed)

| 규칙 | 동작 |
|---|---|
| `AdvanceRatio ∉ [0.0, 1.0]` | **임포트 FAIL** (외삽 금지 — 1.2는 타겟을 지나쳐 통과한다) |
| `AdvanceRatio` 공란 | **임포트 FAIL** (0으로 무음 캐스팅되면 근접이 제자리 타격이 된다) |
| 런타임 방어 | 그래도 범위 밖 값이 들어오면 `Clamp(0,1)` + **로그 1줄**(무음 클램프 금지) |

### 4-4. 명명 — `AdvanceRatio` **유지**

| 후보 | 판정 |
|---|---|
| `AdvanceRatio` **유지** | **채택.** plan·qa·gameplay·balance 4개 문서와 청사진에서 이미 이 이름으로 통용된다. §4-2 정의문이 모호성("아군 힐은 뒤로 가는데 Advance?")을 완전히 제거하므로, 개명 이득 < **크로스 문서 드리프트 비용** |

## 7. 패시브 실행 계약 (구현 명세)

### 7-1. 호출 대상 — `ApplySkillEffects` 아님 (판정3)

```
RunEffectBucket(Caster, SkillId, Timing, ContextTargets[])   ← 신규(현행 3-패스 버킷 파라미터화 추출)
ApplySkillEffects(...)  =  쿨다운 세팅 + BattleLog 1줄 + RunEffectBucket ×3(PRE/ON/POST)
패시브                  =  RunEffectBucket(Owner, Owner.PassiveId, <Timing>, [Owner])
                              ↑ 쿨다운 0 · BattleLog 0 → 오라클 diff 무영향
```
⚠ `RunEffectBucket` 추출은 **F7b 수술** → **⑦ 게이트 GREEN 이후 별도 커밋**(⑦ 커밋에 절대 포함 금지 — ⑦은 단독 게이트).

### 7-2. 훅 2종 (알파). 나머지 5종은 **어휘만 예약**

| 훅 | 콜사이트 | 순회 순서 | 진입 조건 | 로그 |
|---|---|---|---|---|
| **`ON_BATTLE_START`** | `StartBattle` 말미 — **턴 큐 정렬 후, 첫 `EnterTurnStart` 전** | **슬롯 인덱스 오름차순**(A1..A4, B1..B4) 고정 = 결정론 | `PassiveId != 0` | `PassiveLog\| phase=BATTLE_START unit=<slot> passive=<id> applied=<n>` |
| **`ON_TURN_START`** | `EnterTurnStart` 말미 — **SKIP_TURN(TS4) 판정 뒤** | 단일 유닛 | `PassiveId != 0` ∧ `bAlive` ∧ `!bBattleOver` ∧ **`!bSkipThisTurn`** | `PassiveLog\| phase=TURN_START unit=<slot> passive=<id> turn=<T> applied=<n>` |

**예약(어휘만, `Timing` 화이트리스트 미포함 — 임포트 FAIL 대상)**: `ON_DAMAGED` · `ON_KILL` · `ON_DEATH` · `ON_HEALED` · `ON_TURN_END`.

> ★**`SKIP_TURN` 시 `ON_TURN_START` 패시브는 발동하지 않는다** (본 문서 확정). 사유 3: (a) `ON_TURN_START`는 *"자기 턴에 무언가를 한다"* = 행동성이 있고, STUN이 행동을 무는 것이 어휘상 자연스럽다 (b) **fail-closed** — 덜 발동하는 쪽이 안전측 (c) plan §패시브 위험이 지적한 *"패시브만 무적"* 문제에 **STUN이라는 카운터 손잡이 1개**를 남긴다. `ON_BATTLE_START`(상시형)는 여전히 카운터 불가이므로 balance 상한(§12)이 그쪽을 담당한다.
> 이견 시 변경 지점 = 위 표의 `!bSkipThisTurn` 조건 1개.

### 7-3. 상시형 패시브의 구현 경로 (신규 코드 0)

```
ON_BATTLE_START → RunEffectBucket → EffectType=STATUS → ApplyStatus(Owner, <영구 상태>)
                                                          ↑ 검증된 기존 함수
이후 곱연산은 GetOutgoingAtkMult / IN_MULT 채널이 자동 처리 → 신규 훅 0
```
- **영구 sentinel**: `status_effects.DefaultDuration = -1`. `TickStatusesAtTurnEnd`에 **분기 1개** 추가 — `if (dur == -1) continue`(차감 안 함).
- `StackPolicy=REFRESH`가 `-1`을 `-1`로 덮으므로 재부여도 무해.
- 사망 시 상태 Clear 경로는 **기존 그대로**(영구 상태도 예외 없이 정리).
- 부수 이득: F7 §8-7(b)가 베타로 미룬 *"지속형 SELF_BUFF skip 마커"* 문제가 **영구 상태엔 만료가 없어 자연 회피**된다.

### 7-4. 재귀 가드 (필수 — 스코프 축소와 무관)

| 항목 | 확정 |
|---|---|
| 필드 | `PassiveReentryDepth : int` (`BP_BattleManager` 멤버) |
| 규칙 | `RunEffectBucket` **패시브 경로** 진입 시 `+1`, 이탈 시 `-1` |
