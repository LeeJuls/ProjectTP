## `AU-A4-10/11` — 신규 토큰 2종

| 순번 | 토큰 | 카테고리 | 문법 |
|---|---|---|---|
| **19** | `FXLAB:STGNOROW:<stagingId>` | **ERROR** | colon_pos |
| **20** | `FXLAB:RESOLVE:<skillId>:<stagingId>:<fxCast>:<fxProj>:<fxImpact>` | **STAGE** | colon_pos |

**카테고리 근거**:
- `STGNOROW`=**ERROR** — 15b(`FXNOROW`)와 동형인 fail-loud다. STAGE에 두면 **베타에서 끄는 순간 침묵**한다
- `RESOLVE`≠**DIAG** — ★DIAG는 **기본 OFF**라 `AU-A5-05`(상류 1홉 관통 판정)가 **실행 불가**가 된다(qa 지적)

### ★문법이 pipe가 아니라 colon인 이유 — 규약 예외를 명문화했다

LOG-A 계약서는 *"신규 토큰은 pipe key=value"*다(순번16~18). 19·20은 **colon**이라 위반처럼 보이므로 `tokens.py` docstring에 근거를 박았다:

1. **계열 일관성이 규약보다 구체적이다** — `FXLAB:` 형제 4종이 전부 colon이고 파서가 한 덩어리로 다룬다
2. **pipe의 이점이 안 산다** — pipe kv의 핵심은 *"필드가 늘어도 위치가 안 밀린다"*인데, 19는 1필드이고 20은 **5필드 전부 숫자 ID 고정**이다. `BattleLog`의 `died`처럼 유무로 자리가 밀리는 **가변 필드가 없다**(그 사고가 pipe 채택의 실제 동기였다)
3. FXLAB은 **실험대 전용 진단 계열**이지 라이브 원장이 아니다 — pipe 규약의 대상은 LEDGER/FLOW이고 실제로 16~18이 전부 그쪽이다

★**규약은 유지된다**: *"라이브 원장·흐름 신규는 pipe / FXLAB 실험대 계열은 계열 문법"*. ★이 예외를 안 적어두면 다음 사람이 *"규약 위반"*으로 보고 pipe로 "고쳐" `PrintString` 리터럴과 어긋나게 만든다 — **3주 드리프트가 난 방식 그대로**다.

### 검증

```
30/30 PASS (환경변수 없음)
match_row 충돌 0 — STGNOROW→19 / RESOLVE→20 / FXNOROW→15b 정확 분기
전투로그.md §3 재생성 — 20종 전량 카테고리 배정, 누락 0
```
