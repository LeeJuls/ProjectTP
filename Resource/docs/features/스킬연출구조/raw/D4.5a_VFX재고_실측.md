## 0. 요약 (Director 3줄 보고의 근거)

1. **`ColorRow` 사용 가능** — row0~5는 180/180 파일에서 색 계열이 100% 일관(row5=무채색 확정). row6~8은 89~96%만 일관, 예외 7~19개 파일 존재 → **정수 축으로 쓰되 6~8은 파일별 `RowHues` 대조 필수**.

### ★row5 유채색 0의 원인 — 규명 완료

`Part 1\03.png` row5를 alpha·RGB 직접 스캔한 결과:

| | row5 (문제의 행) | 다른 행(예: row0) |
|---|---|---|
| alpha>0 픽셀 수 | 8484 (다른 행과 **동일**) | 8484 |
| 채도>0.15 픽셀 수 | **0** | 8484 |
| median Saturation | 0.000 | 0.545 |
| median RGB (alpha>0 샘플) | R=G=B=**0.62** (완전 무채색 회색) | R=0.96 G=0.58 B=0.44 |

**결론: 가설 A(무채색 변형) 확정, 가설 B(빈 행) 기각.** row5는 alpha 픽셀 수가 다른 8개 행과 **정확히 동일**(같은 실루엣) — 완전 투명이 아니라 **회색/무채색 팔레트 변형**이다. 180장 전수 스캔에서도 **"완전 빈 행(alpha 전무)"은 0건** — row5는 항상 내용이 있고 항상 무채색이다(아래 §3).

→ **`ColorRow` 어휘는 `0~8`(9개 전부 유효 색 슬롯)이다. `0~7+1`(빈 슬롯 1개)이 아니다.** row5는 "색 없음"이 아니라 "무채색(백/회 계열) 색상"으로 취급해야 한다 — 예: 신성/치유/얼음 계열처럼 흰빛이 필요한 스킬에 유효 슬롯.

## 2. `ColorRow` 어휘 확정 권고 (핵심 판정)

### 2-1. 그리드 구조는 100% 균일

| 항목 | 값 | 일관성 |
|---|---|---|
| GridY(행 수) | **9** | 180/180 (100%) |

| row2 | 청록-파랑 (191.4°~211.3°, 가장 좁음) | **180/180 (100%)** | 가장 안전 |
| row3 | 황록-초록 (79.2°~143.1°) | **180/180 (100%)** | 안전 |

**권고**: `vfx.csv`에서 row6~8을 색상 지정에 쓸 스킬은 반드시 해당 파일의 `RowHues`를 CSV에서 대조한 뒤 확정한다. row0~5만 쓰는 스킬은 대조 없이 안전.

## 5. UE 임포트 시 필요한 세팅 (명세만, 미실행)

### 5-1. 텍스처 임포트 — 기존 `T_FX_Smear`/`T_FX_Hit`와 동일

기존 결정 기록(`VFX_임시통합_방침.md`) 재확인 세팅:

```
filter: TF_Nearest
mipGenSettings: TMGS_NoMipmaps
compressionSettings: TC_EditorIcon
```

**동일하게 적용 가능. 다른 점 없음.** 이 팩도 픽셀아트 SubUV 시트라 조건이 같다(알파 채널 사용, 색상+투명 혼재, 밉맵/압축이 도트를 뭉갤 위험도 동일).

### 5-2. 머티리얼/MI — 신규 개발 0, GridY>1 이미 실증됨

`M_Sprite_Flipbook_Lit` 계열(`A0_합성머티리얼스파이크.md` 실측)의 UV 계산식:

```
V = (LocalV + RowIndex) / GridY
FinalUV = (U, V)
```

이 수식은 **GridY=17짜리 마스터에서 `RowIndex=2` 오버라이드 → `get_scalar_parameter` 재조회로 정확히 반영**됨을 이미 실증한 코드다. 지금 필요한 건 GridY=9(9가 17보다 작은 값)이라 **같은 수식이 그대로 성립** — 신규 노드·신규 파라미터 불필요.

**단, 실사용 이력 차이**: 기존 `MI_FX_Smear`/`MI_FX_Hit`는 지금까지 `GridY=1`로만 써서 **RowIndex를 실제로 색상 선택 용도로 굴려본 적은 없다**(항상 0). GridY=17 실증은 캐릭터 합성(`M_Sprite_PartComposite`)에서 나온 것이고 VFX 전용 MI에서 GridY=9로 굴리는 조합은 **미실행**이다. → 코드 리스크는 0에 가깝지만, D4.5 이후 실제 MI 1개를 GridY=9로 세팅해 `RowIndex` 순회 재생 확인은 **art-pipeline이 처음 해보는 조합**이니 1회 스팟 검증 권고.

### 5-3. `vfx.csv` 컬럼별 채움 가능성

| 컬럼 | 채울 수 있는가 | 근거 |
|---|---|---|
| `TexPath` | 가능 | D4.5 행 배정 후 `/Game/VFX/T_FX_<이름>` 규칙으로 임포트 예정 경로 확정 |
| `GridX` | 가능 | 이 CSV `GridX` 컬럼 그대로 |
| `GridY` | 가능(전부 9) | §3 |
| `ColorRow` | **조건부 가능** | row0~5는 안전, row6~8은 파일별 `RowHues` 대조 필요(§2-2) |
| `FrameCount` | 가능(=GridX) | §3, 0건 불일치 |
| `FPS` | **불가 — 데이터 없음** | 픽셀에서 유도되는 값이 아니라 재생 속도 판단(디자인 영역). 기존 `T_FX_Smear`/`Hit` 컨벤션 `FPS=15` 참고 가능하다고만 적을 수 있음. **추측 금지 원칙상 "미확인 — art/design 육안 판단 필요"로 남긴다** |
