# AT4-b 결과 — PlayCameraCut + STGDEFAULT 폴백 + arcHeight 포물선 (MCP 세션, 2026-08-12)

> 선행: [[AT4-a_결과_2026-08-12]] · 상위: `D1_4슬롯구조_확정.md` E14 · `E_TC.md` E-S3-05/06 · `tokens.py` 순번21·22·23

## 결론 5줄

1. ★**가장 중요한 발견**: 3건(카메라 컷·STGDEFAULT 폴백·arcHeight 포물선) **전부 이미 구현이 끝나 있었다.** 지시서의 "미구현" 판단은 **파일 mtime만 보고 내린 것**이라 틀렸다 — MCP가 붙는 대상은 **살아있는 에디터 프로세스의 메모리**이고, 그 프로세스가 재시작되지 않은 채 유지되고 있어서 전 세션(AT4-b-1)이 만든 그래프가 저장 전 상태 그대로 남아 있었다(디스크 mtime은 저장을 안 했으니 AT4-a 시점 그대로 — 앞뒤가 안 맞는 게 아니라 정확히 이 이유였다).
2. **3건 전부 PIE 실측 PASS** — ① `PlayCameraCut`(SetViewTargetWithBlend 왕복 + `FXLAB:CAMCUT`/`FXLAB:CAMBACK` 로그) ② `ResolveStaging`의 `StagingIdIn==0` → `FXLAB:STGDEFAULT:62000100` → 재귀 폴백 ③ `PlayApproach`의 `Z = ArcHeightIn × 4 × Ratio × (1−Ratio)` 포물선 공식 — 테스트값(Ratio=0.5, ArcHeight=50)으로 액터 Z가 정확히 100→150(+50)까지 오르는 것을 실측 확인.
3. ★**arcHeight 관련 신규 발견**: 라이브 `DT_Stagings` 4행은 `AdvanceRatio`가 **항상 0 또는 1**(중간값 없음 — 애니메이션이 아니라 단발성 `SetActorLocation`)이라, 포물선 공식 `4·r·(1−r)`이 **끝값에서 항상 0**이 된다. 즉 arcHeight 값을 아무리 키워도 **현재 데이터로는 영구히 시각적 차이가 없다** — 이건 클램프(raw≤-0.0001 sentinel) 때문이 아니라 **Ratio가 구간 내부값을 갖지 않는 구조적 이유**다. 공식 자체는 Ratio=0.5에서 검증 완료(정확히 일치).
4. **컴파일 에러 0**(`compile_blueprint` 성공) · **저장 2건**(`BP_FxLabDummy.uasset`, `map_battle_fxlab.umap`) 즉시 커밋(`de62a27`) · `tokens.py`+`전투로그.md` 즉시 커밋(`dca6a4c`) · **의도치 않은 변경 0건**(`BP_BattleManager`/`BP_FxLabQuad`/`WBP_SkillMenu` 전부 `is_dirty=false` 확인 — 함정102 재발 없음).
5. ★**60fps 관측(미확인#1 해소)**: `max tick rate 3` 확인(함정100 확정사항과 일치, 기대대로). **60이 아니었으므로 추가 보고 불요.**

## 사전 확인 — 전 세션(AT4-b-1) 산출물의 실재 (구현 안 함, 실측만)

PM 지시서가 "미구현"이라 판단한 3건을 코드 레벨로 직접 조회(`find_nodes`/`get_connected_subgraph`)해 확인한 결과:

### ① `ResolveStaging` — `StagingIdIn==0` 분기 (E14 폴백)

`IfThenElse_6`(Branch, Condition = `StagingIdIn == 0`):
- **then(true)** → `CallFunction_20`(PrintString `"FXLAB:STGDEFAULT:" + ToString(DefaultStagingId)`) → `CallFunction_21`(`ResolveStaging` 재귀 호출, `StagingIdIn=DefaultStagingId`)
- **else(false)** → `GetDataTableRow_0`(기존 AT4-a 정상 조회 경로, 무변경)

`DefaultStagingId` 변수(CDO) 실측값 = **`62000100`** — 지시서 권고값과 정확히 일치.

### ② `PlayCameraCut`(EventGraph Custom Event, `K2Node_CustomEvent_2`)

```
PlayCameraCut → SetViewTargetWithBlend(PlayerController(0), NewViewTarget=CameraCutTargetRef, BlendTime=0.3, VTBlend_Linear)
  → PrintString "FXLAB:CAMCUT:"
  → RetriggerableDelay(0.5)
  → SetViewTargetWithBlend(PlayerController(0), NewViewTarget=DefaultCameraRef, BlendTime=0.3, VTBlend_Linear)
  → PrintString "FXLAB:CAMBACK:"
```

`ResolveStaging`의 `IsCameraCutFlag==true` 분기에서 `AlignBillboardToCamera` 다음에 `PlayCameraCut` 호출(기존 AT4-a 구조에 이어붙임).

인스턴스 변수(레벨 액터 `BP_FxLabDummy_C_0`) 실측:
```
cameraCutTargetRef → /Game/Stages/map_battle_fxlab...CameraActor_3
defaultCameraRef   → /Game/Stages/map_battle_fxlab...CameraActor_0
```
PM 지시서가 언급한 기존 배치 2개(`CameraActor_0`·`CameraActor_3`)가 **정확히 이 두 변수에 배선되어 있었다** — 신규 카메라 액터를 만들 필요 없음, 재사용 확인.

★**사양과의 사소한 차이(수정 안 함, 보고만)**: 지시서 문구는 "`FXLAB:CAMBACK`(복귀 직전)"인데, 실제 그래프는 `SetViewTargetWithBlend(DefaultCameraRef)` **호출 후** 로그를 찍는다(CAMCUT과 대칭 — "발동 직후"). 즉 문자 그대로는 "복귀 직전"이 아니라 "복귀 직후"다. 기능적으로는 문제 없음(뷰타겟 전환·사이클 완주·로그 1:1 짝 전부 정상), E-S3-05 TC도 순서를 요구하지 않는다. **근본 원인 없는 수정 금지 원칙에 따라 건드리지 않고 보고만** 한다 — qa-critic/PM 판단 필요.

### ③ `PlayApproach` — arcHeight 포물선

```
ZOffset = ArcHeightIn × (Ratio × (1.0 − Ratio)) × 4.0
FinalLocation = Lerp(HomeLocation, AnchorLocation, Ratio) + (0, 0, ZOffset)
SetActorLocation(FinalLocation)
```
표준 포물선 공식(0→1 구간에서 t=0.5일 때 정점=ArcHeightIn, 양끝 t=0/1에서 0) 그대로.

전 세션(AT4-b-1)이 죽기 전 남긴 로그(같은 에디터 프로세스 로그 파일에 누적):
```

06.51.47:154 FXLAB:CAMCUT:

```
본 세션에서 재트리거(`DebugStagingId: 999999→0`)해 재현:
```
07.44.08:652 FXLAB:STGDEFAULT:62000100
07.44.08:652 FXLAB:CAMCUT:
07.44.08:986 FXLAB:CAMBACK:
```
`STGDEFAULT`(id=0) → `62000100`으로 재귀 → 그 행이 `isCameraCut=true`라 `PlayCameraCut` 발화 — **폴백과 카메라 컷이 사슬로 연결**되어 동작함을 확인. CAMCUT→CAMBACK 델타 = 0.334s(3fps 틱 굵기 때문에 0.5s 리터럴과 다름 — 함정100 영향, 정밀 타이밍은 기존대로 이월).

### 게이팅 — `isCameraCut=false` 행은 CAMCUT 미발화

`DebugStagingId=62000400`(`isCameraCut=false`) 트리거 후 로그 재조회 → **신규 CAMCUT/CAMBACK 라인 0건** 추가. 분기가 실제로 게이팅함을 확인(AT4-a의 `AlignBillboardToCamera` 게이팅 확인과 동형 결과).

### STGNOROW 유지 확인

`DebugStagingId=999999`(미존재) → `FXLAB:STGNOROW:999999` 1줄, AT4-a 경로 무변경 확인.

### arcHeight 포물선 — 공식 검증(테스트값, 원복 완료)

라이브 4행이 전부 `AdvanceRatio∈{0,1}`이라 시각 차이가 없다는 AT4-a 관찰을 재확인하면서, **공식 자체가 맞는지** 별도 검증했다:

| 단계 | `DT_Stagings.62000200` 임시값 | 트리거 | 실측 액터 Location | 기대값(공식) | 판정 |
|---|---|---|---|---|---|
| 1 | `advanceRatio=0.5, approachArcHeight=50.0` | `DebugStagingId=62000200` | `(150, 0, 150)` | `Lerp((0,0,100),(300,0,100),0.5)=(150,0,100)` + `Z+=50×4×0.5×0.5=50` → `(150,0,150)` | **일치** |
| 2 | `advanceRatio=1.0, approachArcHeight=50.0`(Ratio만 원복) | 동일 stagingId 재트리거 | `(300, 0, 100)` | `4×1×(1-1)=0` → 오프셋 0 | **일치**(끝점에서 0 확인) |
| 3(원복) | `advanceRatio=1.0, approachArcHeight=-1.0`(완전 원복) | — | `get_rows` 재조회 결과 원본과 **필드·메모 전부 동일** | — | **원복 확인** |

★**원복 검증**: `set_rows`로 되돌린 뒤 `get_rows` 전체 재조회 → 4행 전체가 최초 조회값과 완전히 동일(메모 문자열까지). PIE 종료 후 `git status --porcelain`(Content 저장소) 결과도 **공백**(DT_Stagings는 애초에 파일로 재직렬화되지 않았거나, 됐어도 원본과 바이트 동일) — 실측으로 원복을 이중 확인.

★**결론(공식은 맞다, 데이터가 못 보여준다)**: 포물선 구현은 정상이나, **현재 `DT_Stagings` 4행의 `AdvanceRatio`가 전부 0 또는 1이라 어떤 arcHeight 값을 넣어도 라이브에서는 절대 보이지 않는다.** 이건 클램프 로직 문제가 아니라 "접근/복귀가 애니메이션이 아니라 즉시 스냅"이라는 데이터 모델의 구조적 한계다. **판정 불가 항목이 아니라 "공식 검증 PASS + 데이터 유효범위 밖"**이므로 D6 이월 사유로 기록한다(아래).
