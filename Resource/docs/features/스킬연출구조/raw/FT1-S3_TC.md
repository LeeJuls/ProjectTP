## 0. 이 문서가 무엇이고 무엇이 아닌가

### 0-1. ★단계 TC는 게이트가 아니라 정지선이다

[[FT1-S3_착수판정]]은 **노드 17개·연결 17건·핀값 7건을 한 번에 심고 끝에 게이트 6건**으로 검증한다. 실패하면 원인이 변수 신설인지·타입 불일치인지·분기 극성인지·호출 연결인지 **분리되지 않는다.** 본 문서는 그 앞단에 **9개의 확인 지점**을 넣는다.

| | 단계 TC (`AU-FSTP-*`, 본 문서) | 최종 게이트 (`AU-FAS-*`, 착수판정 §4) |
|---|---|---|
| 누가 | **gameplay-engineer**(수술 세션 중, 자가확인) | **verifier**(수술 세션 **종료 후 별도 발주**) |
| 무엇 | *"다음 단계로 가도 되는가"* — 진행 판단·조기 국소화 | *"S3이 통과인가"* — 게이트 판정 |
| 판정력 | ★**없다.** CLAUDE.md ★★"구현자 자가검증 금지" 규율 그대로 | ★**있다.** PM 게이트 판정의 근거 |
| 실패하면 | 그 단계만 롤백 → 재시도 또는 정지·보고 | S3 FAIL → 정지선(§6) 매핑 → director |

★★**단계 TC 전량 PASS는 `AU-FAS-*` 중 어느 하나도 대체하지 않는다.** 두 층은 다른 사람이 다른 시점에 다른 목적으로 본다. 단계 TC는 Part A 보고서(§3-6의 9개 인용 의무)를 **구조화하는 틀**이기도 하다 — 인용해야 할 원문이 어느 단계에서 나오는지가 표로 고정된다.

### 0-3. ★3fps 제약 (함정100 실무규칙 2·3)

에이전트 PIE는 `max tick rate 3`이고 **바꿀 수 없다**(3회 조사 확정, 함정(100)·(105)). 본 문서의 전 TC는 **카운트 · 순서 · 논리값 · 핀 원문 diff · 정수 카운터 부등**만 판정한다.

- ★**타이밍 값(초·ms·델타) 판정 0건.** `Duration=0.1`은 *"핀에 그 문자열이 들어갔는가"*(정적 diff)로만 다루고, *"0.1초 뒤에 실행됐는가"*는 판정하지 않는다.
- `max tick rate` 값은 **기록 의무**이되 PASS/FAIL 근거 아님(`AU-FSTP-27`).

## 1. ★단계 분할 — 9단계, 경계와 그 근거

### 1-1. 분할 원칙 3가지

1. ★**중간 상태가 반드시 "컴파일되고 · 실행되지 않는" 상태여야 한다.** 부착점 `ExecutionSequence_0.then_0`이 비어 있는 한 신규 17노드는 **exec 진입점 없는 고아 섬**이고 런타임 영향이 0이다 — [[FT1-S2_착수판정]] §3-4가 *"`break_pins`(C1) 1건 절단 → 스캐폴드 전체가 고아 섬(부작용 0)"*으로 이미 실증한 성질이다.
2. ★★**"arm last" — 부착 연결을 맨 마지막에 한다.** 착수판정 §3-2의 연결 나열은 `ExecutionSequence_0.then_0→N1`이 **첫 번째**다. 그 순서로 심으면 그 시점부터 체인이 **라이브가 되고**, 아직 배선되지 않은 `N12.Condition`이 기본값 `false`로 읽혀 **`N12.False→FIRE` 경로가 성립한다** — 수술 중 무장 해제 상태로 전투가 시작될 수 있다. 본 분할은 이 연결을 **D7로 밀어** 전 중간 상태를 증명 가능하게 무해화한다(§4-F6).
3. ★**비가역성이 늦게 오게 배치한다.** D1(조회)은 완전 무료 → D2(변수)가 **최초 비가역 지점**(MCP 변수 삭제 툴 부재, §4-F11) → D8(저장)이 **에이전트 최종 비가역 지점**(`git restore` 권한 없음, 함정102 해법3).

#### [High] F1 — `BattleState` **정수** ↔ N5 **`Equal(Byte)`** 복제 지시가 한 문서 안에서 상충

#### [High] F2 — `Delay(0.1)` 존치 근거는 **`AU-FAS-04`로 검증되지 않는다**(교락)
- **주장**(§2-다): *"latent 재개는 전 액터 BeginPlay 디스패치 완료 후 틱이므로 … **가드를 순서 무관으로 만드는 부품**"*, 그리고 *"단정이 아니라 **게이트가 검증하는 구조**다"*(`AU-FAS-04`의 `INIT < FIRE`).
- **반박**: ★`AU-FAS-04`는 이 주장을 **판별하지 못한다.** [[FT1-S2_04판정]] §2가 이 레벨의 실제 순서를 확정했다 — SpawnPoint 8기가 먼저 돌고 `InitBattle()`이 **동기 완주**한 뒤 Manager BeginPlay가 최후다. 즉 **`INIT < FIRE`는 `Delay`가 있든 없든 성립한다.** `Delay`의 주장된 효용은 *"순서가 뒤집힌 레벨"*이라는 **이 레벨이 보이지 않는 반사실**에서만 발현하므로, 실제 런의 순서 관측으로는 *"Delay가 일한다"*와 *"Delay가 무해한 no-op이다"*가 **구분되지 않는다.**

#### [High] F4 — 정지선 7건이 **놓친 실패 모드 3종**
- ⓐ ★**off-런에서 `MA:AUTOSTART:GUARDFAIL:*` ≥1**: `AU-FAS-02`는 FAIL이지만 **어느 정지선에도 매핑되지 않는다** — #1은 *"on-런에서"*로 한정되고, #4는 `State:TurnStart` ≥1만 본다. 의미는 *"오버라이드가 없는데 토글이 true로 읽혔다"* = CDO 오염 또는 변수 읽기 이상으로, **정지선 #4와 같은 급의 신호**다. 도달 가능: `AU-FSTP-06`이 실패했는데 그대로 진행한 경우.

#### [Medium-High] F5 — `AU-FAS-02`는 **사전 상태 시험**이라 토글 오염을 절반만 잡는다
- **문제**: Part B 순서는 `02(off) → 03(on, 오버라이드 set) → 05(원복·git)`이다. 즉 ★**"원복 후 off 행동"을 확인하는 런이 없다.** `AU-FAS-05`가 확인하는 것은 **프로퍼티 읽기값**(`get_properties`=false)과 **디스크**(git porcelain)뿐이다.
- **읽기값의 부분 방어(정직 고지)**: on 쪽에서 `get_properties`가 `true`를 읽어야 `AU-FAS-03`이 진행되므로, *"읽기가 CDO를 보고 있다"*는 가설은 대체로 배제된다 — 이 축은 director 설계가 이미 막았다.
- **남는 갭**: ★**`git clean ≠ not dirty`.** [[FT1-S1_조회결과_2026-08-13]] §8이 *"`is_dirty=true`인데 `git status --porcelain`은 공백"*을 **이 프로젝트에서 직접 실측**했다. 오버라이드 사이클은 `.umap`을 **인메모리 dirty**로 남길 수 있고, `AU-FAS-05`는 그것을 보지 않는다. 잔존 dirty는 이후 아무 세션에서 누군가 "모두 저장"을 누르는 순간 디스크에 도달한다 — 착수판정 §2-라가 *"에디터 수동 모두 저장은 막을 수 없다"*로 인정한 바로 그 잔여 위험이 **검출 없이** 살아 있다.
- **재현**: on 사이클 후 `set_properties(false)` → `get_properties`=false → git 공백 → **PASS** → 그러나 `is_dirty(<레벨>)`은 true인 채 세션 종료 → 다음 세션의 저장 1회로 오염 확정.
- **확신도**: 순서 비대칭 = **CONFIRMED** / dirty 잔존 = **PLAUSIBLE**(S1의 BP 사례는 실측, 레벨 인스턴스 사례는 미실측).
- **처분 권고**: `AU-FAS-05`에 ⓐ*"`is_dirty(<레벨>)` 조회값을 원복 전/후 인용"* ⓑ★*"원복 후 off-런 1회 — `MA:AUTOSTART` 0건"*(PIE +1회, 행동으로 원복을 증명) 추가.

#### [Medium] F7 — `AU-FAS-03`에 **PIE 최소 유지 조건**이 없다

#### [Low-Medium] F8 — `tokens.py` GUARDFAIL의 `syntax`가 **자기 근거와 반대**
- **위치**: §3-4 ⓑ — *"syntax **COLON_POS**"*인데 같은 항의 note 지시문이 *"colon인 이유 — **고정 리터럴 4종(가변 필드 0)**이라 pipe 이점이 없고"*.

- **반대 해석도 기록**: 4번째 세그먼트(`state|queue|lock`)를 *"도메인이 3원소인 위치 필드"*로 보면 COLON_POS도 방어 가능하다. **어느 쪽이든 근거와 값이 일치해야 한다.**
- **확신도**: 문서 내 자기모순 = **CONFIRMED** / 어느 값이 옳은가 = **PLAUSIBLE(PLAIN 우세)**.
- **처분 권고**: director가 택1하고 note를 그에 맞게 정정. `AU-FSTP-32`가 이 판정을 기다린다.

| **`qlen>0`을 하중 조건으로 삼은 판단** | ✅ 결론 타당(논거는 보강 권고) | 결론은 옳다. 다만 §2-나의 논거(*"큐를 채우는 것은 compact뿐이므로 qlen>0 ⇔ 초기화 완주"*)보다 **더 강한 실측 논거**가 이미 있다 — [[FT1-S2_04판정]] §2가 *"8번째 `Register`에서 `InitBattle()`이 **동기 완주**함을 로그 순서가 증명"*했다. **동기 완주이므로 다른 프레임에서의 중간 상태 관측이 원리적으로 불가능**하다는 것이 진짜 근거다(`Delay`가 프레임을 넘기므로 더욱). 논거 교체 권고, 판정 변경 불요 |
| **토글 = 인스턴스 오버라이드 채택** | ✅ 타당 | CDO 인메모리 기각 근거(*"이 세션의 저장 대상이 바로 그 uasset"*)가 정확하다. 폭발 반경 비교도 옳다. 잔여 위험은 F5로 분리했다 |
| **`AU-FAS-02`의 `SessionBoundary\| 정확 1건` 요구** | ✅ 부수 효과로 유용 | S2 회귀 확인이 주목적이나, **`BP_BattleManager` 인스턴스가 레벨에 2기 이상 존재하는 경우**(마커 2줄·FIRE 2줄)를 함께 걸러낸다 — 정지선 #2(FIRE ≥2)와 원인 분리에 도움 |
