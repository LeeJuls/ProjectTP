# D5.5 — 오너 수동 struct 세션 절차서

> 상위: [[plan]] · 근거: [[D1_4슬롯구조_확정]] §R-1 · [[D4_게이트판정]]
> **이 문서는 오너가 UE 에디터 앞에서 보는 실행 절차서다.**

## 왜 오너가 직접 해야 하나

**MCP로 struct를 만들거나 필드를 추가할 수 없다.** 토큰셋 어디에도 struct 생성·편집 툴이 없다(`search_row_structs`는 검색 전용). A0③ 스파이크에서 이미 확인된 제약이다.

DataTable **애셋 생성**은 MCP가 대행할 수 있다(`DataTableTools.create`). 즉 **오너 몫은 struct 6건뿐**이고 DT 3개는 Claude가 만든다.

## ★진입 조건 — 현재 1/2

| # | 조건 | 상태 |
|---|---|---|
| ① | **D4.5 완료** — `stagings`/`vfx`/`sfx` 스키마가 실데이터로 확정 | ✅ **충족**(2026-08-11) |
| ② | **F7b ⑩a 스톱 체크리스트 GREEN** | ❌ **미충족** — ⑦도 아직이다(`EnterExecuting`이 여전히 `ResolveHit` 직접 호출) |

조건 ②는 **"제거 10건" 때문에만 필요하다.** `powerRate`·`effectType` 등 구컬럼을 지금 지우면 **라이브 전투가 즉시 깨진다**(`ResolveHit`이 아직 그 값을 읽는다).

→ 그래서 선택지가 둘이다.

## 선택지 — 지금 할까, 기다릴까

### A안 — 1세션 (D1 원안 권고)

⑩a GREEN까지 기다렸다가 **6애셋을 한 번에** 처리한다.

- **장점**: 모달 노출 **1회**. 함정㉓ 비용이 최소
- **단점**: ⑦→⑧→⑨→⑩a를 다 거쳐야 하므로 **한참 뒤**다. 그동안 `stagings`/`vfx`/`sfx` CSV는 `drafts/`에만 있고 **엔진엔 아무것도 안 들어간다**

### B안 — 2세션 (지금 신규 3종만 먼저) ★Director 권고

지금 **신규 struct 3종만** 만들고, 나머지는 ⑩a 후에.

| 세션 | 시점 | 대상 | 성격 |
|---|---|---|---|
| **1차** | **지금 가능** | `F_StagingsRow` · `F_VfxRow` · `F_SfxRow` | **순수 추가 — 무파괴.** 기존 애셋 무접촉 |
| **2차** | ⑩a GREEN 후 | `F_SkillsRow`(추가6/제거10) · `F_JobStatsRow` · `F_MotionsRow` | 제거 포함 — 라이브 영향 |

- **장점**: 1차 직후 Claude가 `DT_Stagings`/`DT_Vfx`/`DT_Sfx`를 MCP로 만들고 **CSV를 실제로 임포트**할 수 있다 → 스키마·값이 **엔진에서 검증**된다. 설계 오류를 지금 잡는다
- **단점**: 모달 노출 **2회**

> **Director 판단**: 함정㉓의 비용은 "그 시간 동안 Claude가 MCP를 못 쓴다"이지 파괴적 위험이 아니다. 반면 **설계 전량이 엔진 미검증 상태로 ⑩a까지 방치되는 위험**이 더 크다. `vfx.csv` 인용 위반이 산출 직후에 발견됐듯, 임포트해봐야 드러나는 문제가 있다.

## 공통 주의사항 (세션 시작 전 반드시)

| # | 주의 |
|---|---|
| **1** | ★**세션 중 Claude는 MCP를 쓸 수 없다.** struct 편집 모달이 열려 있으면 브릿지 전체가 멈춘다(함정㉓). 편집을 **끝내고 모달을 닫은 뒤** 알려주면 그때부터 다시 작업한다 |
| **2** | **DataTable 에셋을 전부 닫고** 시작한다. 열린 채로 struct를 바꾸면 값이 꼬일 수 있다 |
| **3** | **필드명은 대소문자까지 정확히.** UE는 struct 필드를 `stagingId`로 만들면 CSV 헤더 `StagingId`와 매칭한다(첫 글자 대소문자 무관). 단 **철자가 틀리면 조용히 매칭 실패**하고 기본값이 들어간다 |
| **4** | 저장은 **Ctrl+S**, 그리고 Content Browser에서 **Save All** |

## 1차 세션 절차 — 신규 struct 3종 (지금 가능)

### 만드는 위치

**`/Game/Data/Structs/`** (오너 결재 2026-08-11)

### 공통 조작

```
Content Browser에서 /Game/Data/Structs/ 폴더로 이동
→ 우클릭 → Blueprints → Structure
→ 이름 입력 → 더블클릭으로 열기
→ "Add Variable" 버튼으로 필드 추가
→ 각 필드의 이름·타입·기본값 설정
→ Ctrl+S
```

⚠ UE가 struct를 만들면 **`MemberVar_0` 같은 기본 필드 1개가 자동 생성**된다. 그걸 첫 필드로 **이름만 바꿔 쓰거나**, 지우고 새로 추가하면 된다.

### ① `F_StagingsRow` — 연출 프로필 (4행이 들어갈 테이블)

| 필드명 | 타입 | 기본값 |
|---|---|---|
| `advanceRatio` | **Float** | `0.0` |
| `approachMotionRow` | **Integer** | `-1` |
| `approachArcHeight` | **Float** | `0.0` |
| `isCameraCut` | **Boolean** | `false` |
| `isTargetFlinch` | **Boolean** | `false` |
| `memo` | **String** | (공란) |

> `approachMotionRow`의 기본값이 `-1`인 이유: `0`은 Idle 모션이라 "없음"과 구별이 안 된다.

### ② `F_VfxRow` — 이펙트 (5행)

| 필드명 | 타입 | 기본값 |
|---|---|---|
| `texPath` | **String** | (공란) |
| `colorRow` | **Integer** | `0` |
| `gridX` | **Integer** | `1` |
| `gridY` | **Integer** | `1` |
| `frameCount` | **Integer** | `1` |
| `fps` | **Float** | `10.0` |
| `memo` | **String** | (공란) |

> `texPath`가 String인 이유: 이 프로젝트에 SoftObjectPath DT 컬럼 전례가 없다. 기존 FX 컬럼도 전부 String이었다. 런타임에 경로로 로드한다.

### ③ `F_SfxRow` — 사운드 (3행, 알파는 슬롯만)

| 필드명 | 타입 | 기본값 |
|---|---|---|
| `soundPath` | **String** | `NONE` |
| `volume` | **Float** | `1.0` |
| `pitch` | **Float** | `1.0` |
| `memo` | **String** | (공란) |

> 오디오 애셋이 0개라 전 행이 `NONE`이다. **공란이 아니라 `NONE` 토큰**인 이유는 "없다"와 "안 채웠다"를 구별하기 위해서다.

### 1차 세션 후 Claude가 할 일

모달을 닫고 알려주면:
1. `DT_Stagings`·`DT_Vfx`·`DT_Sfx` 애셋을 MCP로 생성
2. `data/drafts/`의 CSV 3종을 임포트
3. **임포트 결과 검증** — 필드 매칭 실패·값 유실이 없는지 실측
4. `#` 접두어 컬럼이 실제로 무시되는지 확인(Q7)

## 2차 세션 절차 — 기존 struct 편집 (⑩a GREEN 후)

### ④ `F_SkillsRow` — 추가 6 / 제거 10

**추가할 필드 6개** (전부 **Integer**, 기본값 **0**)

| 필드명 | 용도 |
|---|---|
| `stagingId` | 연출 프로필 FK |
| `fxCastId` | 캐스트 VFX FK (`0`이면 모션 기본값으로 폴백) |
| `fxProjectileId` | 투사 VFX FK (`0` = 즉발) |
| `fxImpactId` | 임팩트 VFX FK |
| `sfxCastId` | 캐스트 SFX FK |
| `sfxImpactId` | 임팩트 SFX FK |

**제거할 필드 10개**

| 필드명 | 왜 지우나 |
|---|---|
| `castFX` · `projectileFX` · `impactFX` · `castSFX` · `impactSFX` | 전부 String이고 **라이브 값이 전 행 `""`**. 위 정수 FK로 교체 |
| `powerRate` · `effectType` · `effectValue` · `effectDurationTurns` · `effectChance` | **F7b ⑩a 구컬럼.** `skill_effects.csv`로 이관 완료 후에만 |

> ★**제거 5건(아래 줄)은 ⑩a 스톱 체크리스트가 GREEN이어야 한다.** 그 전에 지우면 라이브 전투가 깨진다.

### ⑤ `F_JobStatsRow`

| 조작 | 필드명 | 타입 | 기본값 |
|---|---|---|---|
| 추가 | `passiveId` | **Integer** | `0` |

### ⑥ `F_MotionsRow`

| 조작 | 필드명 | 타입 | 기본값 |
|---|---|---|---|
| 추가 | `fxMotionId` | **Integer** | `0` |
| 추가 | `sfxMotionId` | **Integer** | `0` |
| **제거** | `isAttackFamily` | — | — |

> `isAttackFamily`는 **런지와 잔상을 동시에 게이팅**하는 불리언이라 둘을 따로 못 켠다. `fxMotionId`로 분해하면 파이어볼처럼 "전진은 빼고 잔상은 유지"가 표현된다.

## enum은 만들 필요 없다 (D4 실측 확정)

`Kind`·`Target`·`Category`가 enum이면 **애셋 3개를 더 만들어야 했다.** D4 게이트에서 실측으로 닫혔다:

- `/Game/Data` 전수 조회 결과 **UEnum 애셋 0개**
- `get_schema`·`list_properties` 둘 다 `{"type":"string"}`

→ **전부 FString. 오너 작업 증분 0.** CSV 값만 바꾸면 된다.

## 세션 후 검증 (Claude가 실행)

| # | 확인 |
|---|---|
| 1 | 각 struct의 필드 목록이 위 표와 **정확히 일치**하는가(`list_properties`) |
| 2 | DT 임포트 시 **필드 매칭 실패 0** — 철자 오류가 있으면 값이 조용히 기본값으로 들어간다 |
| 3 | `#` 접두어 컬럼(`#Layer` 등)이 실제로 struct에 안 들어가는가 |
| 4 | 2차 세션 후: **라이브 5스킬 회귀 무손상** + 오라클 diff |
