## 0. ID 네이밍 — ★발주 지시에서 1건 이탈했다 (PM 확인 요망)

발주서는 `AU-F1-0a-01`을 예시했으나, **기존에 `AU-F1-01a` / `AU-F1-01b`가 실재**한다([[자율진행_TC]] §FT1). `AU-F1-0a-01` ↔ `AU-F1-01a`는 **문자 순서만 다른 사실상 동형 문자열**이라 grep·표 대조·구두 전달에서 뒤섞인다. 발주서의 구속 조건은 *"충돌 없게"*이므로 그쪽을 우선했다.

| 채택 | 대상 | 기존 충돌 |
|---|---|---|
| `AU-F0a-nn` | FT1-0a (`SessionBoundary\|`) | `AU-F0*` 패밀리 **부재** — 충돌 0 |
| `AU-F0b-nn` | FT1-0b (`PlayAttack\|`) | 〃 |
| `AU-F0c-nn` | FT1-0c (`SkillSelected\|`) | 〃 |
| `AU-F0x-nn` | 공통(카테고리 bool·계약서·회귀) | 〃 |
| `AU-F0p-nn` | ★**선행 프로브**(착수 차단 게이트) | 〃 |

PM이 발주서 표기를 고수한다면 일괄 치환은 1회 sed로 끝난다 — **다만 그 경우 `AU-F1-01a`와의 혼동 위험을 인수하는 것**임을 기록해 둔다.

**주체 표기**(기존 계승): `M`=기계·문서 대조 / `V`=verifier(PIE 필요) / `O`=오너 세션 필요 / `V+O`=오너 런을 verifier가 판정

- **확신도**: **CONFIRMED**
- **처분**: 와일드카드 우선순위 규칙(**최장 일치 우선**)을 계약서에 명문화하고, `FXLAB:DIAG`를 **DIAG 행에 명시적 예외**로 못 박는다.

#### [Medium-High] fail-loud 신호를 STAGE에 넣었다 — **끄면 에러 보고가 침묵한다**
- **위치**: STAGE 행의 `FXLAB:*`
- **문제**: `FXSKIP`/`TEXMISS`/`FXNOROW`는 점검 §1-1이 *"fail-loud 설계(행 없음·프레임 0·텍스처 캐스트 실패를 각각 구분)"*로 규정한 **정식 오류 신호**다. STAGE 수명은 *"개발 중"*이라 베타에 끈다 → **오류가 조용해진다.**
- **일반화**: 4카테고리 분류축은 *"언제 끌 것인가(수명)"* 하나뿐인데, **fail-loud는 수명이 LEDGER급이면서 성격은 진단**이다. 축이 모자라서 갈 곳이 없다. 점검 §2-4가 지적한 *"`Accessed None`을 우리 토큰으로 못 잡는다"*도 같은 구멍이다.
- **확신도**: **CONFIRMED**
- **처분 권고**: **5번째 카테고리 `ERROR`(수명 영구 · 기본 ON · 끄기 금지)** 신설, 또는 fail-loud 3종을 LEDGER로 이관. 어느 쪽이든 *"끌 수 있는 오류 신호"*를 남기지 말 것.

#### [Medium-High] 4 bool 토글이 **[[features/스킬연출구조/plan|plan]] §10 미확인 3의 자연 검증을 무효화**한다
- **위치**: [[로그시스템_개선_plan]] §10-3 — *"`PrintString`이 턴 델타에 유의미한 시간을 더하는지 → **세션 2의 60fps 관측에서 1.750 재확인**으로 자연 검증"*
- **문제**: 그 자연 검증은 **로그 출력량이 통제변수**일 때만 성립한다. 이번에 도입하는 토글은 정확히 그 변수를 **세션마다 바꿀 수 있게** 만든다. STAGE만 꺼도 세션당 ~700줄(**전체의 70%**)이 사라진다 → 1.750이 재확인돼도 *"PrintString 비용이 없었다"*인지 *"비용은 있었는데 로그를 껐다"*인지 **분리 불가**.
- **재현**: 세션 2를 `bLogStage=false`로 돌린다 → 델타가 줄어든다 → 결론이 오염된다.
- **확신도**: **CONFIRMED**
- **처분**: `AU-F0x-05`(마커에 4 bool 상태 동봉) + `AU-F0x-02`(전 인스턴스 기본값 일치)로 닫는다. **세션 2 지시서에 "4 bool 기본값 유지" 1줄**을 넣을 것.

#### [Medium] `bPrintToLog` 방식 — *"노드 추가 0"*은 **거짓**이다
- **위치**: LOG-A §구현 비교표(`bPrintToLog` 핀 연결 행: 신규 애셋 0 / **노드 추가 0** / exec 무접촉)
- **문제**: bool 변수를 핀에 연결하려면 그래프마다 **`Get <변수>` 노드(K2Node_VariableGet)가 추가**된다. **결론(exec 무접촉)은 참**이지만 **"노드 추가 0"은 틀렸다.** 이 프로젝트는 *"노드 수 무변(스냅샷 텍스트 diff)"*을 실제 PASS 기준으로 쓴다(`AU-F1-02`·`AU-A5-05`) → **기존 회귀 기준과 충돌**한다.
- **확신도**: **CONFIRMED**
- **처분**: 표 문구를 *"**exec 노드** 추가 0 / 순수 데이터 노드 `Get` N개 추가"*로 정정하고, 노드 수 무변을 요구하는 TC에 **"순수 Get 증가분은 예외"**를 명기.

#### [Medium] carve-out 판정 *"기존 15종 이관은 splice 불필요"*는 **맞지만, 무접촉은 아니다**
- **문제**: 핀 연결만 해도 (i) `.uasset`이 dirty → **저장·커밋 대상** (ii) 컴파일 재수행 → 함정(66)의 `No then pin found` 경고 개수가 변할 수 있다 (iii) 레벨 인스턴스 오버라이드가 생기면 **`.umap`도 dirty**. *"carve-out 불필요"*는 **exec 축 한정**이고, **세이브포인트·회귀 축에서는 여전히 라이브 수술**이다.
- **확신도**: **CONFIRMED**
- **처분**: FT1-0 세이브포인트 SHA256 manifest에 **`.umap` 포함**을 명기.

#### [Medium] `sid` 단위 = **PIE 세션**인데 **원장 단위는 전투**다
- **문제**: `BeginPlay`는 PIE당 1회. 그런데 **한 PIE 안에서 전투를 여러 번** 돌릴 수 있다(현황도 §2-6: *"Attack/Start 버튼 재클릭 → `InitBattle`부터 재시작"*, 로그의 `State|event=INIT|mode=RESTART`). 즉 **1 sid에 원장 2벌**이 들어갈 수 있고, 오라클 20행 diff가 40행을 보게 된다.
- **재현**: PIE 1회 안에서 전투를 2판 → `SessionBoundary|` 1줄 / `BattleLog|` 2배.
- **확신도**: **CONFIRMED**(수단은 이미 있다 — `State|event=INIT`. 문제는 **계약이 "세션 필터=sid"라고만 적었다는 것**)
- **처분**: 계약서에 **세션 키 = `(sid, INIT 발생 순번)`**을 명문화. [[features/스킬연출구조/plan|plan]] §6 FT1-1a의 *"세션 필터(sid) 사용"* 문구도 같이 정정.

#### [Medium] `SessionBoundary|`·`PlayAttack|`·`SkillSelected|`의 **필드 목록이 미정**
- **문제**: 계약이 정한 것은 *"pipe key=value"*와 *"`sid`는 세션 내 불변·세션 간 유일"* 뿐이다. 필드명·필수/선택·유닛 식별자 표기가 없다. 이 상태로 `AU-F0a-03`(핀 원문 "삽입 외 동일")은 **통과하면서 파싱 불능인 라인**을 낳을 수 있다 — 게이트가 형상만 보고 내용을 안 본다.
- ★특히 **유닛 식별자**: `BattleLog|attacker=SpawnPoint_Party_A3`와 **같은 표기**를 써야 LOG-A ②-1 접두어 스트립이 재사용된다. `PlayAttack|`이 `unit=A3`나 표시명을 쓰면 **조인 규칙이 갈라진다.**
- **확신도**: **CONFIRMED**
- **처분**: 계약서에 3종의 **필드 스키마 표**(필드명 / 필수 / 값 형식 / 예시 1줄)를 넣고, *"유닛 식별자는 전 토큰에서 `SpawnPoint_<Team>_<Slot>` 원문 1형식"*을 못 박는다.

#### [Low] `enter`/`exit` 표기 방식 미정 — `phase=` 필드 vs 토큰 분리
- `PlayAttack|...|phase=enter` 인지 `PlayAttackEnter|` 인지에 따라 **grep 카운트 커맨드와 카테고리 와일드카드 매칭이 달라진다.** 계약서에서 택1. (본 TC는 `phase=` 가정으로 작성했다 — 와일드카드 오염이 적다.)

#### [Low] `t=` 필드의 의미 미고지
- 기존 `t=`는 **PIE 시작 이후 누적 월드시간이며 리셋되지 않는다**(점검 §2-3). 3fps 세션에선 ~333ms로 양자화된다. 계약서에 *"`t=`는 RAW 월드초 · 세션 간 비교 불가 · 3fps 세션에서 판정 근거로 쓰지 않는다"* 1줄 필요.

### 3-C. ★안 깨진 것 (검토했고 통과시킨 축과 근거)

| 축 | 판정 | 근거 |
|---|---|---|
| **`TakeHit*` → STAGE** | ✅ 타당 | 용도가 전부 **연출 검증**이다(피격-복귀 레이스 ≥0.35s 마진, 막타 히트VFX N19 — 점검 §1-1). 끄더라도 데미지 사실은 `BattleLog\|dmg`(LEDGER)에 남는다 → 원장 판정력 손실 0 |
| **`ExecWalkPhase:` → FLOW** | ✅ 타당 | 턴길이 실측의 앵커지만 그 측정은 **알파~베타 개발 활동**이고, 같은 측정에 필요한 `PlayAttack\|`도 FLOW라 **함께 켜지고 함께 꺼진다**(자기정합). 단 §3-B 「4 bool이 §10-3 자연검증 무효화」 항의 통제 조건은 별도로 걸어야 한다 |
| **`FXLAB:*` → STAGE**(fail-loud 3종 제외) | ✅ 부분 타당 | `FXSHOW`/`FXHIDE`(성공 경로)는 STAGE가 맞다. **깨진 것은 `DIAG` 중복 소속과 fail-loud 3종**이며 §3-B에 별항으로 분리했다 |
| **`SkillSelected\|` → FLOW**(LEDGER 아님) | ✅ 타당 | 오너 질문 ①의 목적이 *"UI 버그 시 재현밖에 방법이 없다"* = **개발기 진단**이다. 또 `AU-B2-05`가 *"`target`은 입력이지 출력이 아니다 → 판정력 없음"*을 이미 확정했으므로 **입력 계열은 원장이 아니다**가 프로젝트 기존 판정과 정합 ⚠단 계약서에 *"FLOW를 끄면 오너 질문 ①은 다시 답할 수 없게 된다"* 고지 1줄 권고 |
| **DIAG 기본 OFF 자체** | ✅ 타당 | `FXLAB:DIAG`가 실제로 임시 진단인 채 잔존한 실측 사례가 있다(점검 §3-3). **깨진 것은 방향이 아니라 "켜는 절차 부재"**이고 `AU-F0x-04`로 요구했다 |
| **`bPrintToLog` 핀 연결이 exec를 안 건드린다** | ✅ 타당(핵심 주장은 참) | `PrintString`은 이미 exec 체인 안에 있고 bool 입력은 **데이터 핀**이다. 연결해도 exec 위상 변화 0 ∧ 노드는 계속 실행되되 출력만 안 한다. **깨진 것은 부수 주장 3개**(노드 추가 0 / 무접촉 / 변수 소재)이며 §3-B에 분리 |
| **splice carve-out을 신규 3종으로 한정** | ✅ 타당 | 기존 15종은 노드가 이미 있어 핀 연결뿐 → exec 절단 0이 맞다. **범위 한정 판단 자체는 정확하다** |
| **FT1-0a가 카운트 기반이라 3fps에서 판정 가능** | ✅ 타당 | `BeginPlay`는 **클릭 없이 발화**하므로 함정(99) 벽 밖이고, 카운트는 tick rate 무관. `max tick rate` 명기 의무만 지키면 된다(`AU-F0a-01`) |
| **`enum`/`TPLog()` 대신 핀 연결을 고른 판단** | ✅ 타당 | 함정㉓(UEnum 생성 시 블로킹 모달 → MCP 전면 마비) 실증이 있고, 함수 교체는 호출부마다 exec 절단이다. **비교 결론은 옳다** |
