| # | 경로 | 결과 | 원인 |

| 4 | 콘솔 명령 | ❌ | 전 툴셋 레지스트리에 콘솔 명령 실행 툴 없음(`SearchCVars`는 조회 전용) |

### ★막힌 지점은 정확히 **1개**다

`BP_BattleManager`가 상태를 로깅한다: `Init → TurnStart → AwaitCommand → AwaitTarget → UnitClicked → ExecWalkPhase → BattleLog → TurnEnd`

verifier 세션은 8기 `Registered` 후 **`State:Init:t=0`에서 수 분간 전혀 전진하지 않았다.** → 막힌 건 **"Start" 클릭 단 1회**이고, 그 뒤는 자동 진행된다.

★**이 지점 1개만 뚫으면 라이브 전투 검증 전체가 열린다.** 우회책 후보(콘솔 명령 훅 추가 · 디버그 전용 BP 함수 노출 · 자동 시작 토글)를 설계할 때 **`ClickBox`의 네이티브 `OnClicked` 델리게이트**가 정확한 출발점이다.

## ★verifier의 반증 회피 — 기록해둘 가치가 있다

세션 로그에 `TakeHit` · `BattleLog|dmg=32` 등 **전투가 실제로 돈 흔적**이 남아 있었다. 그대로 *"검증됨"*으로 처리할 수 있었다.

verifier는 **타임스탬프를 대조**해 그것이 **절단 전 베이스라인 저장(14:33:28) ~ 최종 절단 저장(16:18:06) 사이**의 데이터임을 확인하고 **배제**했다. 최종본에 PIE를 돌린 건 자기 세션이 유일했고, 거기선 아무것도 못 얻었다.

★이건 이 프로젝트가 반복해온 오판(**과거 관측을 현재 검증으로 착각**)을 스스로 막은 사례다.

## ★tick rate 3 — 원인 해석 (Director 판단)

verifier 관찰: `SlateInspector` 창 **0개** · `CaptureEditorImage` 실패 · 반면 `CaptureViewport`(렌더타깃 경유)는 **정상**.
verifier 결론: *"이 MCP 에디터 세션은 OS 레벨 창이 0개(헤드리스)"*.

★**Director 판단: 관찰은 사실이나 "창이 0개"라는 해석은 과잉이다.**

**반증**: 오너가 **에디터 스크린샷을 여러 장 보냈다**(2026-08-11~12). 창은 실재한다. 그리고 오너가 직접 켠 PIE는 `max tick rate 60`이었다(로그 실측 5회).

**더 정합한 설명**: 창은 존재하되 **백그라운드/비활성** 상태이고, Slate 열거 API가 그 상태에서 창을 못 잡는다.

★**그러나 실무 결론은 동일하다**:

| | 사람이 앞에 있을 때 | 에이전트가 돌릴 때 |
|---|---|---|
| tick rate | **60** | **3** |
| 전투 진행 | 클릭 가능 | ❌ 불가 |

→ **에이전트 PIE로는 타이밍 검증도 전투 진행도 할 수 없다.** 원인이 "창 부재"든 "창 비활성"이든 **에이전트가 바꿀 수 없다**는 점은 같다.
