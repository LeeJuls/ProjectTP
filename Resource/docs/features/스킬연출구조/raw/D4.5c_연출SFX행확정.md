### 2-2. ★`1.0` 계약이 깨지는 경로 1개 발견 — D1 §4-2 정정 필요

현행 `WalkForward`의 `WalkTargetLoc` 3단 우선순위(`docs/features/걸어나오기연출/청사진.md` · 같은 폴더 `TC.md` WT-01~03 실측):

```
① AttackPointOverride  ② 팀 AttackPoint  ③ 폴백 = HomeLocation + (±300, 0, 0)
```

D1 §4-2 v2 `ResolveApproachAnchor`의 최종 폴백은 **`PrimaryTarget.Loc`**이다.

| 경로 | 현행 | D1 §4-2 v2 | 일치 |
|---|---|---|---|
| ① Override | Override 위치 | 동일 | ✅ |
| ② 팀 포인트 | AttackPoint 위치 | 동일 | ✅ |
| **③ 폴백** | **`HomeLocation ± 300`**(WT-03 실측: `X=679.149` = Home `979.149` + `(-300)` 정확 일치) | **`PrimaryTarget.Loc`** | ❌ **캐스터가 타겟 위치에 정확히 겹친다** |

- **알파 발현 여부**: 씬에 `AttackPoint_Party`/`AttackPoint_Enemy`가 실재하므로 **경로 ③은 현재 발현하지 않는다**(WT-03은 강제 None 세팅 테스트였다). 그러나 그 액터가 삭제·레벨 교체되면 즉시 발현하고, **회귀 0 주장이 조용히 거짓이 된다**.
- **정정안(신규 코드 최소)**: 적 타겟 분기 안에 현행 폴백을 **보존**하고, `PrimaryTarget.Loc` 폴백은 아군 타겟 전용으로 축소.

```
ResolveApproachAnchor(Caster, PrimaryTarget):
  if (PrimaryTarget == Caster)              return Caster.Loc
  if (AttackPointOverride is valid)         return AttackPointOverride
  if (PrimaryTarget.Team != Caster.Team):
      if (AttackPoint_<Caster.Team> exists) return AttackPoint.Loc
      return <현행 WalkForward 폴백식 그대로>          ← ★추가(회귀 0 복원)
  return PrimaryTarget.Loc                              ← 아군 타겟 전용(알파 미발현: 서포트=0.0)
```

- **비용**: BP 분기 1개. 신규 상수 0(현행 폴백 계산 노드를 그대로 재사용). D1 §4-2 v2가 노린 Y12(*"치유하러 적진으로 걸어간다"*) 방어는 **그대로 유지**된다 — 아군 경로는 여전히 적 앵커를 반환하지 않는다.

### 3-3. ★"비었다" vs "없다" — `SoundPath = NONE` 규약

`PassiveId` 공란 금지(D1 §1-1)와 **동형 문제**다. 구별해야 할 상태는 3개이고, 실제로는 2개만 필요하다.

| 상태 | 표현 위치 | 값 | 소비 노드 동작 |
|---|---|---|---|
| **참조 자체가 없다** (이 스킬/모션은 소리를 안 낸다) | **참조 측** — `skills.Sfx*Id` / `motions.SfxMotionId` | **`0`** | `sfx` 조회 **자체를 안 함** |
| **슬롯은 있고 소리가 아직 없다** (알파 정상) | `sfx.SoundPath` | **`NONE`** | 유효성 체크 → **스킵. 로그 0줄**(정상 상태이므로 fail-loud 아님) |
| **슬롯은 있고 소리가 배정됐다** | `sfx.SoundPath` | `/Game/Audio/SFX_...` | 재생. **로드 실패 시** 로그 1줄 + 스킵(E17) |
| ~~안 채운 실수~~ | `sfx.SoundPath` | **공란 `""`** | **린트 FAIL** — 이 값은 데이터에 존재해서는 안 된다 |

- **왜 공란이 아니라 `NONE`인가**: DT String 임포트는 공란을 `""`로 넣는다. 즉 *"소리를 아직 안 붙였다"*와 *"셀을 안 채웠다"*가 CSV 위에서 **구별 불가**해진다. 오디오가 실제로 들어오는 시점에 어느 행이 의도적 무음이고 어느 행이 누락인지 판별할 수 없다.
- **어휘 신규 0**: 라이브가 이미 `EffectType=NONE`·`Target=NONE`·`StatTarget=NONE`·`StatusEffectId=NONE`을 쓴다(`status_effects.csv`·`skill_effects.csv` 실측). `SFX_` 애셋 접두사와도 충돌하지 않는다(경로는 항상 `/Game/`으로 시작).
- **신설 린트 L30 (T1, `sfx`)**: `SoundPath == "NONE"` ∨ `SoundPath`가 `/Game/`으로 시작. **공란은 FAIL.**
- **art-pipeline 인계 권고**: `vfx.TexPath`도 동일 규약(`NONE` 허용 · 공란 FAIL)을 쓰면 L30이 `vfx`/`sfx` **한 코드**가 된다. 단 `vfx`는 D4.5-b에서 전 행 실경로가 채워질 예정이라 강제는 아님.

### 3-4. `sfx`가 `vfx`와 **동형이 아닌** 지점 1개 — 의도적

### 8-4. 접근 모션 재생 계약 부재 — 비루프 모션이 접근 중 idle로 복귀한다

- `ApproachMotionRow`의 중립값 `-1`은 row2(`Run1`, `IsLoop=TRUE`)라 접근 시간 동안 루프한다. 그러나 **도약 프로필이 지정한 row4(`Jump`)는 `IsLoop=FALSE` ∧ `EndBehavior=REVERT_IDLE`**이다. 재생 시간 < 접근 시간이면 **도약 도중 idle 자세로 복귀**한다(공중에 서 있는 그림).
- **확정 계약 (신규 컬럼 0 · 신규 상수 0)**:

```
접근 모션 재생 FPS = motions[ApproachMotionRow].FrameCount / ApproachSec
   (루프 모션이면 이 식을 적용하지 않고 기존 재생 유지)
```

  - 기각 A: `IsLoop==TRUE`만 허용 → row4가 배제되어 **도약 프로필이 성립 불가**.
  - 기각 B: 비루프는 `EndBehavior==FREEZE_LAST`만 허용 → row4는 `REVERT_IDLE`이라 결함 그대로.
  - 채택 근거: 스프라이트 재생 속도는 이미 MI `FPS` 스칼라로 제어된다(`VFX_임시통합_방침` 실측: `MI_FX_Smear`/`MI_FX_Hit`의 `FPS` 15→10 세팅 성공). 접근 시간이 상수이고 프레임 수가 데이터이므로 **FPS가 유일한 자유 변수**다.
  - 참고 산식: `ApproachSec` = 현행 `WalkForward` latent **0.4s**(`docs/features/걸어나오기연출/청사진.md`) → row4는 `8 / 0.4 = 20 FPS`.
- **미확인 (D6)**: 캐릭터 MI(`MI_Party_A1` 등)에 `FPS` 스칼라 파라미터가 실재하는지. `PlayAttack`이 세팅하는 것은 `TimeOffset`/`FrameCount`/`RowIndex` 3종으로만 기록돼 있다 → **`get_scalar_parameter(MI_Party_A1, "FPS")` 1회로 확정.** 부재하면 계약을 `FrameCount` 조정으로 대체해야 하며 그때 재설계.
