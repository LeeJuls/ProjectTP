# 스킬 → 모션·연출·이펙트 연결 구조 (청사진)

> 오너 지시(2026-08-10): *"캐릭터 공격 구조에 맞는 기본공격 + 스킬에 맞는 모션 + 연출 + 이펙트를 정하는 게 더 중요. **각 캐릭터 테이블에 어떻게 연결할지에 대한 구조 설계가 가장 중요**하다."*
> 상위: [[알파_개발계획]] A2 · 선행: [[모션연결_규칙안]](E1-B 확정) · [[F7b_재개계획_초안]] · [[전투VFX_방향]] · [[balance1_포지션킷_v1]]

## 문제 — 4층 중 2층만 데이터다

스킬 하나가 화면에 나타나려면 **4개 층**이 필요하다:

| 층 | 질문 | 현재 상태 |
|---|---|---|
| ① **판정** | 얼마나 아픈가 / 무슨 효과인가 | ✅ 데이터 — `DT_SkillEffects` + F7b 인터프리터 |
| ② **모션** | 어떤 동작을 하는가 | ✅ 데이터 — `skills.csv MotionRow` → `motions.csv` 17행 |
| ③ **연출** | **걸어가나? 제자리인가? 카메라는?** | ❌ **BP 하드코딩** — `ENEMY1/ALLY1/SELF` 분기 |
| ④ **이펙트** | **어떤 VFX가 언제 어디서** | ❌ **BP 하드코딩** — 공격=Smear, 피격=Hit 고정 |

**③④가 데이터가 아니면 A2에서 벽에 부딪힌다.** 30원자 × 3슬롯 × 1000캐릭터인데, 원자마다 연출·이펙트가 다르면 BP 분기로는 감당이 안 된다. 오너 룰(하드코딩 금지)에도 정면 위배다.

## 이 기능의 목표

**③ 연출과 ④ 이펙트를 데이터화**하고, **캐릭터 테이블 → 스킬 3슬롯 → 각 층**으로 이어지는 해석 경로를 확정한다.

```
characters.csv (1000행)
   └ 3슬롯: 평타1 + 공용1 + 직업1  → skills.csv (30원자)
                                      ├ ① EffectRow  → DT_SkillEffects  (F7b가 해석)
                                      ├ ② MotionRow  → DT_Motions       (F6이 해석)
                                      ├ ③ 연출Row    → ???              ← 이번 설계
                                      └ ④ 이펙트Row  → ???              ← 이번 설계
```

## 범위 / 비범위

**범위**: ③④의 **데이터 스키마 + 해석 규칙 + 캐릭터 테이블 연결 구조**. 30원자에 실제 값 배정. 기존 5스킬을 새 구조로 표현해 **회귀 없음** 증명.

**비범위**:
- ① 판정 재설계 — **F7b 소관**(중복 설계 금지)
- ② 모션 규칙 재론 — [[모션연결_규칙안]] E1-B 확정분 계승
- 1000행 `characters.csv` 생성 — A2 스크립트 몫
- 신규 VFX 제작 — 재고(픽셀 VFX 팩 180종) 우선
- BP 구현 — 설계 확정 후 별도 단계

## ★설계 제약 (Director)

1. **과설계 금지** — 원자가 30개뿐이다. 컬럼이 15개가 되면 틀렸다. **balance가 손으로 30행을 채울 수 있는 수준**이 상한.
2. **기존 연출 무손상** — 파트3·4에서 오너 육안 PASS를 받은 동작(막기 제자리·치유 제자리 casting·힐 숫자)을 **새 구조로 표현할 수 있어야** 한다. 표현 못 하면 스키마가 부족한 것.
3. **재고 우선** — 모션 17행 · 픽셀 VFX 180종(64×64, **9색 변형 내장**) · `Holy VFX` 3단 구성(Initial/Repeatable/Impact)이 이미 있다. **재고로 표현 가능한 스키마**를 설계하라.
4. **2D 스프라이트 주력** — [[전투VFX_방향]] 확정. 이펙트 본체는 2D, 3D는 순간 라이트·잔재만.
5. **하드코딩 금지** — 문자열 리터럴 분기(`"ENEMY1"` 비교 등)를 새로 만들지 마라. F7b ⑥이 기존 리터럴을 걷어내는 중이다.

## ⚠ 이 문서는 3슬롯 전제로 작성됐다 (2026-08-11 정정)

오너가 **4슬롯(3 액티브 + 1 패시브)**으로 구조를 변경했다. 본문 전체(§문제·§목표·§열린질문·§DoD)의 "3슬롯" 서술은 **스테일**이다(§문제 "30원자 × 3슬롯 × 1000캐릭터", §DoD "characters.csv 1000행이 3슬롯을 참조" 포함). 확정 구조·판정은 [[features/스킬연출구조/plan|plan]]을 보라.

원문은 판단 과정 기록으로 보존한다.

## 열린 질문 (설계가 답할 것)

1. **연출 프로필이 몇 종류인가?** 근접 접근 / 원거리 제자리 / 자기대상 / 방어 — 4종이면 충분한가, 더 필요한가? 이걸 **enum으로 둘지, 파라미터 조합으로 둘지**.
2. **이펙트 슬롯이 몇 개인가?** 시전(caster) / 투사(travel) / 착탄(target) / 지속(오라) — `Holy VFX`의 3단 구성과 매칭되는가?
3. **색상 변형을 어떻게 지정하나?** 픽셀 VFX 팩이 9색을 내장 — 스킬이 색 인덱스를 갖나, 속성(Kind)에서 유도하나?
4. **타이밍을 데이터로 둘 것인가?** 모션 프레임과 이펙트 발생 시점의 동기 — `motions.csv FrameCount` 기반 유도 vs 명시 지정.
5. **카메라 컷은 이 층에 포함되나?** 현행 동적 OTS 컷과의 관계.
6. **캐릭터 테이블과의 연결** — 3슬롯을 `characters.csv`가 어떻게 참조하나(스킬 ID 3컬럼? 킷 ID 1컬럼→킷 테이블?).
