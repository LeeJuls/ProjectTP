## 2. 상태머신 — `BattleState`

`BattleState`는 **정수형 변수**(정식 UENUM 에셋이 아니다 — `list_properties` 조회 결과 `"type":"integer"`, enum 목록 없음)다. 상태 이름은 이 문서가 세팅 함수 이름으로 붙인 것이며, 코드에는 이름표가 없고 **매직넘버(0~6)**가 각 함수에 리터럴로 박혀 있다(§5 주의사항 참고).

| 값 | 상태(이 문서의 명명) | 세팅 위치 | 진입 시 하는 일 | 다음 전이 |
|---|---|---|---|---|
| 0 | Init | `InitBattle` | TurnQueue 정리(무효 항목 제거)·인덱스/카운터/`bBattleOver`/`WinningTeam` 리셋, `WBP_BattleHUD` 생성+뷰포트 부착, Start 버튼 표시 | 오너가 Attack/Start 버튼 클릭 → `StartBattle` → `SortTurnQueueBySpd` → TurnStart(1) |
| 1 | TurnStart | `EnterTurnStart` | 다음 유닛 지정(`ActiveUnit`), `MarkerOn`, 전 유닛 쿨다운 −1, `ActiveStatuses` 순회해 `STUN`(문자열 리터럴) 검사 → `bSkipTurn` | 생존·비스킵 → AwaitCommand(2) / 사망 또는 스킵 → **TurnEnd(5)로 직행**(AwaitCommand를 건너뜀, 실측 확인) |
| 2 | AwaitCommand | `EnterAwaitCommand` | `bInputLocked=false`, 전 유닛 `HighlightOff`, Attack 버튼 표시, `SelectedTargets` 초기화, `WBP_SkillMenu.SetActiveUnit(ActiveUnit)` 갱신 | 플레이어가 스킬 선택 → SELF 스킬이면 즉시 Executing(4) / 아니면 AwaitTarget(3) |
| 3 | AwaitTarget | `EnterAwaitTarget` | `ResolveTargetPool`로 유효 타겟 하이라이트, 취소 버튼 표시 | 유닛 클릭(`NotifyUnitClicked`) → Executing(4) |
| 4 | Executing | `EnterExecuting`(커스텀이벤트, EventGraph) | `ResolveHit(Attacker=ActiveUnit, Target=SelectedTargets[0], SkillId=PendingSkillId)` **1회 호출**(실측 — 인자 3개 전부 변수 연결, 리터럴 아님) | **동기적으로 즉시** TurnEnd(5) 호출(실측 — 애니메이션 재생을 기다리지 않음, §5 참고) |
| 5 | TurnEnd | `EnterTurnEnd`(커스텀이벤트, EventGraph) | `TickStatusesAtTurnEnd`(자기 턴 종료 δ 차감) | `bBattleOver`가 false → TurnStart(1) 루프 / true → End(6) |
| 6 | End | `EnterEnd` | `BattleState=6`, 입력 잠금, 전 유닛 `MarkerOff`, **`BattleFinished` 델리게이트 브로드캐스트**, End 화면 표시, 스킬메뉴 숨김 | Attack/Start 버튼(동일 액터) 재클릭 → `InitBattle`부터 재시작(재전투 배선 실측 확인) |

가드(전이 조건) 확인: `NotifySkillSelected`·`NotifyUnitClicked`·`NotifyAttackButtonClicked` 3곳 모두 진입 시 `BattleState` 비교 노드로 자기 상태를 확인한다(예: `NotifySkillSelected`는 `Equal(Byte) B=2`로 AwaitCommand 여부 확인). `bInputLocked` 플래그가 이중 가드로 병행 사용된다.

## 4. 데이터 구동 vs BP 하드코딩 현황 (표3, ★핵심)

| 항목 | 현재 | 소재 | 비고 |
|---|---|---|---|
| 스킬 메타(Kind/PowerRate/쿨다운/단일효과 EffectType·Value·Duration·Chance) | **데이터 구동** | `ResolveHit` — `GetDataTableColumnAsString`×7(`Kind`/`PowerRate`/`EffectType`/`CooldownTurns`/`EffectValue`/`EffectDurationTurns`/`EffectChance`), `DT_Skills` | 이것이 **라이브 판정 경로**다. 신규 3층 모델(`DT_SkillEffects`+`DT_StatusEffects`)은 존재하나 아래 §5 참고 — 완전 별개 경로 |
| 스킬 타겟 토큰(ENEMY1/SELF/ALLY1) — 스킬메뉴 경로 | **데이터 구동**(폴백만 하드코딩) | `NotifySkillSelected` — `GetDataTableRow(DT_Skills)`→`BreakStruct.Target` | RowNotFound 분기에서만 리터럴 `"ENEMY1"` 사용(안전 폴백, 정상 경로 아님) |
| 스킬 애니메이션(MotionRow) | **데이터 구동**(폴백만 하드코딩) | `EnterExecuting`(EventGraph) — `GetDataTableRow(DT_Skills)`→`MotionRow`→`ActiveUnit.PendingMotionRow` | RowNotFound 시 리터럴 `5`(atk1) 폴백 |
| 유닛 스탯(Hp/Atk/Def) | 데이터 구동 | `BP_BattleSpawnPoint` BeginPlay — `DT_JobStats`(JobId 키) | F3 기완료분(변경 없음) |
| 모션 프레임수/루프/EndBehavior | 데이터 구동 | `BP_BattleSpawnPoint` EventGraph — `DT_Motions` | F6 기완료분(변경 없음) |
| 스킬메뉴 3슬롯 목록·이름·쿨다운 표시 | 데이터 구동 | `WBP_SkillMenu.SetActiveUnit` — `DT_JobStats.SkillIds`(`;` 분해)→`DT_Skills` 룩업, 이름은 `ST_UI` 로컬라이즈 | **슬롯 수 3 하드고정**(배열 아님, Row_Skill0/1/2 개별 노드) — Category 탭(F7b §9) 미착수 |
| ★**월드 공격버튼의 SkillId/Target** | **BP 하드코딩** | `BP_BattleManager.NotifyAttackButtonClicked` — `PendingSkillId=31000000`(리터럴)·`PendingTargetToken="ENEMY1"`(리터럴) | 스킬메뉴 경로(`NotifySkillSelected`)와 **이중 진입점**. 한쪽(메뉴)은 DT 경유, 한쪽(월드버튼)은 리터럴 — 31000000이 DT상 실제로 ENEMY1을 가리키는 스킬이라 결과는 같지만, DT에서 그 값이 바뀌면 이 버튼만 안 따라간다 |
| ★**상태이상 채널 판정(STUN/ATK_DOWN)** | **BP 하드코딩** | `EnterTurnStart`(스킵 판정, `"STUN"` 리터럴)·`GetOutgoingAtkMult`(발신배율, `"ATK_DOWN"` 리터럴) — 양쪽 다 `EqualExactly(String)` 직접 비교 | `DT_StatusEffects`(6행, `Channel` 컬럼 보유)로 일반화("`LookupChannel`" 함수)할 계획이었으나 F7b §8-8 그대로 **미착수**. 새 상태(같은 채널이라도)를 추가하면 이 두 지점을 직접 수정해야 함 — "레고 원칙"(새 상태=코드 0) 미달성 |
| ★**`DT_StatusEffects`(6행: STUN/BURN/ATK_DOWN/DEF_DOWN/ATK_UP/DMG_REDUCE)** | **데이터는 있으나 소비 코드 0** | `ApplyStatus` 함수(25노드) 전수 조회 — `DataTable` 참조 노드 0건 | 상태값(세기·지속턴)은 전부 `DT_Skills.EffectValue`/`EffectDurationTurns` 인라인 컬럼에서 나온다. `DT_StatusEffects`는 사실상 미러/미사용 데이터 |
| ★**`DT_SkillEffects`(10행) + 3층 인터프리터 4함수** | **데이터·코드 모두 존재, 완전 미연결(dead)** | §5 표4 참고 | |
| 내부 로그 문자열(팀 라벨 "A"/"B", `State\|`/`BattleLog\|` 등) | BP 하드코딩(리터럴) | `EnterEnd`의 `SelectString(A="A",B="B")` 등 다수 `PrintString` | **`bPrintToScreen=false`·`bPrintToLog=true`** — 사용자 노출 UI가 아니라 개발용 로그 전용이라 로컬라이제이션 대상 아님(참고 표기) |
| 유닛/턴오너 UI 텍스트("Party"/"Enemy" 등) | **로컬라이제이션 키(ST_UI) 준수** | `WBP_SkillMenu` — `Battle.TurnOwner.Party`/`Battle.TurnOwner.Enemy` 등 `MakeTextfromStringTable` | 정상 |

**요약**: 실전투 판정(피해·힐·쿨다운·기존 상태이상 3종)은 **`DT_Skills` 단일 평면 테이블**로 데이터 구동되고 있다. "박혀 있는" 것은 ① 월드 공격버튼의 스킬ID/타겟 2개 리터럴 ② 상태 채널 판정 2곳의 문자열 리터럴 ③ (미가동) 3층 모델 데이터 10+6행 — 총 **3개 지점**이 "아직 안 옮겨진" 부분이다.

## 6. 핵심 함수 동작 요약 (오너용)

- **`EnterTurnStart`**(47노드): 턴 큐에서 다음 유닛을 꺼내 활성화하고, 그 유닛의 스킬 쿨다운을 전부 하나씩 깎는다. 상태이상 목록에 스턴이 있으면 이번 턴을 건너뛰게 표시하고, 스킵 여부와 무관하게 로그를 한 줄 남긴다.
- **`EnterAwaitCommand`**: 플레이어 입력을 받을 준비를 한다. 공격 버튼을 보여주고 스킬 메뉴를 현재 유닛 기준으로 새로고침한다.
- **`NotifySkillSelected`**: 스킬 메뉴에서 스킬을 클릭했을 때 실행. 쿨다운이 남아있으면 막고, DT에서 그 스킬의 타겟 종류(적/아군/자신)를 읽어와 다음 단계(타겟 대기 또는 즉시 실행)로 분기한다.
- **`EnterAwaitTarget`**: 누구를 때릴 수 있는지 계산해서 화면에 강조 표시하고, 클릭을 기다린다.
- **`NotifyUnitClicked`**: 강조된 유닛을 클릭했을 때 실행. 정말 유효한 타겟인지 다시 확인한 뒤 실행 단계로 넘어간다.
- **`ResolveHit`**(169노드, 가장 크고 가장 오래된 함수): 실제 피해/회복/막기/상태이상 적용을 전부 처리하는 단일 거대 함수. 스킬 정보를 DT에서 읽고, 공격력·방어력·배율로 피해를 계산하고, HP를 깎고, 죽었는지 확인하고, 승패까지 이 함수 안에서 결정한다. 상태이상(스턴/공격력약화)도 여기서 굴려서 붙인다.
- **`EnterTurnEnd`**: 방금 행동한 유닛의 상태이상 지속시간을 하나 줄이고, 전투가 끝났는지 확인해서 다음 유닛 턴으로 가거나 전투 종료로 간다.
- **`EnterEnd`**: 전투 종료 처리 — 입력을 잠그고, 승패 화면을 띄우고, "전투 끝났다"는 신호(델리게이트)를 내보낸다.
- **`WBP_SkillMenu.SetActiveUnit`**(111노드): 지금 턴인 유닛의 직업(JobId)으로 배운 스킬 3개를 DT에서 찾아 메뉴 3칸에 채워 넣는다. 쿨다운 중이면 버튼을 비활성화한다.

## 7. 책임 경계 — 누가 무엇을 소유하는가

- **`BP_BattleManager`**: 턴 순서·상태·판정 로직·승패, 스킬/타겟 선택 중개, 카메라, HUD 생성/소유. "전투가 지금 어느 단계인가"의 유일한 소유자(`BattleState`).
- **`BP_BattleSpawnPoint`**: 유닛 1기의 스탯·상태이상·쿨다운·비주얼(스프라이트/모션 재생). Manager가 지시하면(`PendingMotionRow` 세팅 등) 실행만 한다 — 스스로 판정하지 않는다.
- **`WBP_BattleHUD`/`WBP_SkillMenu`**: 화면 표시 전용. `SetActiveUnit`을 Manager가 호출해야만 갱신되며, 스스로 턴을 진행시키지 않는다(단, `NotifySkillSelected`는 Manager로 위임 호출한다는 점에서 얇은 relay).
- **`BP_AttackButton`/`BP_CamToggleButton`**: 순수 입력 relay. 클릭 시 Manager 함수를 부를 뿐 판정 로직이 전혀 없다.

## 8. 주의가 필요한 지점

1. **이중 진입점(스킬ID 결정 경로가 2개)**: 월드 공격버튼(`NotifyAttackButtonClicked`, 리터럴 `31000000`/`"ENEMY1"`)과 스킬 메뉴(`NotifySkillSelected`, DT 조회)가 서로 다른 코드 경로로 같은 결과(기본공격)를 만든다. `DT_Skills`에서 기본공격 행의 `Target`이 바뀌면 메뉴 쪽은 즉시 반영되지만 월드 버튼은 반영되지 않는다 — **이중 진실(dual source of truth)**.
2. **상태 전이가 애니메이션을 기다리지 않는다**: `EnterExecuting`은 `ResolveHit` 리턴 직후 **동기적으로** `EnterTurnEnd`를 호출한다. 반면 피격/사망 애니메이션은 `RetriggerableDelay` 기반 비동기 재생(`PendingHitTarget` 패턴)이다. 즉 로직상 턴은 이미 다음 유닛으로 넘어갔는데 화면에서는 이전 유닛이 아직 맞는 연출을 하고 있을 수 있다 — 버그는 아니지만(기획 확정 사항인지는 미확인) 겹치는 입력이 들어올 경우의 체감에 영향을 줄 수 있는 지점.
3. **무음 실패 가능 지점(폴백)**: `NotifySkillSelected`의 `GetDataTableRow` RowNotFound → `PendingTargetToken="ENEMY1"` 폴백, `EnterExecuting`의 동일 실패 → `PendingMotionRow=5` 폴백. 둘 다 **PrintString(화면 미출력, 로그만)** 로 경고는 남기지만 사용자에게는 아무 일도 없었던 것처럼 진행된다 — `DT_Skills`에 오타나 누락 행이 생기면 조용히 "기본공격처럼" 동작한다.
4. **`BattleState`가 이름 없는 매직넘버**: 정식 Enum 에셋이 아니라 정수 리터럴(0~6)이 함수마다 하드코딩되어 있다. 코드만 보고는 "2가 AwaitCommand"라는 걸 알 수 없다 — 이 문서의 §2 표가 유일한 대응표다. 향후 상태 추가/재배열 시 전 지점을 일일이 찾아 고쳐야 하는 리스크.
5. **`DT_StatusEffects`/`DT_SkillEffects`는 "만들어졌지만 안 쓰인다"**: 밸런스팀이나 기획이 이 두 테이블 값을 고쳐도 게임에는 **전혀 반영되지 않는다**(§4·§5). 실수로 "여기가 SSOT겠지"라고 착각하고 값을 만졌다가 왜 안 바뀌는지 헤맬 수 있는 지점.
6. **`EnterTurnStart`의 스킵 분기가 `EnterAwaitCommand`를 건너뛴다**: 사망/스킵 유닛은 곧장 `EnterTurnEnd`로 가므로, 그 유닛 차례에서는 HUD가 잠깐도 갱신되지 않는다(의도된 설계로 보이나, 화면상 "깜빡임 없이 넘어감"이 맞는지는 오너 육안 확인 필요 — 미확인).

## 9. 미확인 항목 (추측하지 않고 남겨둠)

- `Spd`/`SpdOverride`가 스폰 시 어디서 세팅되는지(DT 소스 여부) — `SortTurnQueueBySpd` 자체는 확인했으나 값의 원천은 이번 조회 범위 밖. 확인하려면 `BP_BattleSpawnPoint`의 `Spd`/`SpdOverride` Set 지점을 EventGraph/UserConstructionScript에서 추가 조회 필요.
- `WBP_SkillMenuRow`의 `OnClicked` 배선이 정확히 `WBP_SkillMenu.NotifySkillSelected`를 호출하는지 — 함수 존재는 확인했으나 그래프 내부 배선까지는 조회하지 않음.
- §8-4의 "스킵 유닛 차례에 HUD가 갱신되지 않는 것"이 기획 의도인지 버그인지 — 코드 사실은 확인했으나 의도 여부는 system-ui-designer 확인 필요.
- 월드 좌표계상 `ResolveTargetPool`의 `ALLY1`/`SELF` 분기 세부 로직 — 이번 조회는 `EnterAwaitTarget`/`NotifyUnitClicked`가 이 함수를 호출한다는 사실까지만 확인, 함수 내부 3분기(ENEMY1/ALLY1/SELF) 각각의 정확한 구현은 미조회.
