# BT-DOC1 — 전투 주제 정본 4개의 경계 설계 (director 판정)

> **결론 3줄**: ① plan v4의 4축(규칙/구조/데이터/검증)을 **유지하되 "구조"→"구현"으로 개명**한다(데이터 "구조"와의 충돌 제거). ② 정본은 **무시간 사실만** 담고 진행 상태는 한 글자도 담지 않는다 — frontmatter·본문 모순 사고의 뿌리가 "사실과 상태의 동거"였다. ③ 92개 원본은 삭제·이동 없이 **3부류(사실원천/현행자산/순수이력)**로 나누고, 전수 귀속 대장(§7)으로 사실 유실을 기계적으로 차단한다.
> 근거 실측: 92개 전수 스캔 — **71개(77%)에 정정·취소선·번복 마커 존재**. 낡은 결론 승격 위험은 국지적이 아니라 전면적이다.
> 관련: [[문서구조_개선plan]] · [[문서화_규칙]]

## §1 판정 — 4축 유지, 명명·위치 확정

| 정본 | 답하는 질문 | 틀렸을 때 고치는 곳 |
|---|---|---|
| `전투_규칙.md` | 전투가 **어떻게 동작해야** 하는가 | 결정 그 자체(공식·의미론·예산) |
| `전투_구현.md` | 그 규칙이 **어디에 어떻게 구현돼** 있는가 | BP 그래프·레벨·머티리얼·위젯 |
| `전투_데이터.md` | 데이터 계약과 **확정값**은 무엇인가 | CSV·DT·struct |

- **4축 유지 근거**: 92개의 실제 내용을 전수 분류한 결과(§7) 다섯 번째 축이 필요한 문서군이 없다. 다섯 번째 후보였던 "진행 상태"는 축이 아니라 **다른 층**(plan 8단계 `battle_status.yaml`+허브)이다 — §3 참조.
- **"구조"→"구현" 개명 근거**: 이 92개에서 "구조"는 두 가지를 동시에 가리킨다(스킬 4슬롯 *데이터 구조* vs BP *구현 구조*). `D1_4슬롯구조_확정`은 이름에 "구조"가 있지만 내용은 struct 편집표·CSV 규약 = **데이터 정본** 소관이다. 이 충돌을 이름에서 제거한다.
- **위치 = `docs/정본/` 신설** (새 파일 생성이므로 "md 이동 금지"와 무충돌):
  - features/ 하위에 두면 "전투완성 **기능의** 문서"로 오독된다 — 정본은 두 기능(전투완성+스킬연출구조)을 가로지르는 **주제** 층이다.
  - 루트는 이미 40개 과밀 + 운용규약(루트 새 md 금지) 위반.
  - plan v4가 "7~8단계는 영역별 반복"(다음: 캐릭터시스템)이라 명시 — `정본/캐릭터_*.md`가 뒤따를 폴더 스키마를 지금 만든다.
  - ⚠ 오너 확인 1건: 폴더명 `정본/`(한글, 파일명 규약과 일치). 반대 시 `canon/`.

## §3 정본이 담지 않는 것 — 진행 상태 (이번 사고 재발 방지의 핵심)

실사고: `전투완성/plan.md` frontmatter "F1~F9 미착수" ↔ 본문 F4~F9 통과. 원인은 **한 문서가 사실과 상태를 겸직**한 것.

- **정본 금지 어휘**: `대기·예정·이월·진행 중·착수·잔여·미완`(진행 서술). 게이트에서 grep으로 기계 검사한다.
- 유일한 예외 = **§미확인** 절: "아직 아무도 모르는 사실"(예: 161셀 전수 대조 미실시·DT_Sfx.soundPath 휴면 결함·IsLoop bool 임포트 검증)은 지식의 상태이므로 정본에 남긴다 — 단 출처와 해소 예정 위치(TC ID) 명기.
- 진행 상태는 plan 8단계 `battle_status.yaml`+허브가 전담. 정본은 그 파일을 **참조조차 하지 않는다**(방향 역전 금지 — 상태 층이 정본을 참조한다).

## §4 원본 92개와 정본의 관계 — 3부류

| 부류 | 정의 | frontmatter 처리 | 예 |
|---|---|---|---|
| **A 사실원천** | 정본이 내용을 흡수하는 확정 스펙·실측 | `canonical: [[정본]]` + 본문 최상단 배너 1줄("현재 사실은 정본에서 조회") | 스탯_전투공식_v1 · D1 · 상태이상_확정 |
| **B 현행자산** | 계속 실행·참조되는 살아있는 문서 | `canonical:`만 (배너 불요 — 대체된 게 아님) | TC 문서군 · SPD원장 오라클 · 오너 절차서 · plan |
| **C 순수이력** | 게이트 기록·세션 서사·스냅샷 | `canonical:` + 배너. **status는 건드리지 않는다**(PASS 기록은 PASS인 채 증거로 남는다) | 야간*_완료 · AT4-* 결과 · F3 스냅샷 |

- **`superseded_by:`는 진짜 대체에만** 쓴다 — "문서 A의 결론이 문서 B로 뒤집히거나 병합된" 경우. 이번 92개에서 확정 대상 3건: `상태이상_타겟범위_설계안`·`상태이상_카탈로그_밸런스` → `[[상태이상_확정]]` / `스킬연출구조/청사진`(3슬롯 스테일) → `[[스킬연출구조/plan]]`. 게이트 기록에 superseded를 남발하면 "증거가 무효"로 읽힌다 — 금지.
- C부류의 사실도 추출한다(부류≠추출 여부): AT4-b-2(FXSHOW 원인)·파트2_SPD_완료(SPD 규칙) 같은 C 문서가 정본급 사실을 품고 있다. 추출 여부는 §7 대장의 "귀속" 컬럼이 결정한다.

## §5 사실 유실·낡은 결론 승격 방지 — 5중 장치

1. **출처 각주 의무** (§2 공통 규칙) — 승격된 모든 사실이 역추적 가능.
2. **신뢰 서열**: 충돌 시 ① 정정문(❌·취소선의 정정 쪽) ② 게이트 판정 문서 ③ 완료 기록 ④ plan 본문 ⑤ **frontmatter(최하위 — 동결 사고 실측 3건**: F4_중단_인수인계·F5-2_TC·야간작업_총결산**)**. 동순위 충돌은 git 커밋 시각. 그래도 안 풀리면 ③으로.
3. **모순대장**: 추출 중 발견한 문서 간 충돌은 **조용히 고르지 않는다** — `raw/정본화_모순대장.md`에 양쪽 원문+출처를 적재하고 PM/director가 판정. 정본 게이트 조건 = 모순대장 잔여 0.
4. **92개 전수 귀속 대장** (§7): 모든 원본이 "추출됨/현행자산/추출할 사실 없음" 중 하나로 소진돼야 게이트 통과 — "빠뜨린 문서"가 구조적으로 불가능해진다.
5. **적대 표본 역검증**: 정본 초안마다 qa-critic이 사실 20건 표본 추출 → 출처 대조 + **"그 출처보다 나중 문서가 이를 뒤집지 않았는가"** 역방향 grep(`정정|번복|철회|폐기|❌` 71개 문서가 검사 대상). 이번 92개의 최상위 위험 실례: **내장트레일 오너 판정(2026-08-12)이 D4.5b·D5의 vfx 5행 전제를 흔들었고 파급 판정이 미종결** — 데이터 정본은 이 행들을 확정값으로 승격하지 말고 §미확인에 "내장트레일 파급 판정 대기(출처: [[내장트레일_채택_오너판정]])"로 적어야 한다. 이것이 낡은 결론 승격의 전형이다.
