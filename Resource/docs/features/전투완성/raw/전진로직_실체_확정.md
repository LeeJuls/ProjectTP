## 4. `BP_BattleSpawnPoint.WalkForward` — `MoveComponentTo`

노드: `/Game/Blueprints/BP_BattleSpawnPoint.BP_BattleSpawnPoint:EventGraph.K2Node_CallFunction_143` (type_id `컴포넌트|MoveComponentTo`)


## 7. (추가) Start 클릭의 하류 함수 실체

`BP_AttackButton.EventGraph`의 `OnClicked(ClickBox)` 바인딩 이벤트: `K2Node_ComponentBoundEvent_0` (type_id `이벤트추가|OnClicked(ClickBox)`) — ★이것은 `UPrimitiveComponent::OnClicked` **멀티캐스트 델리게이트에 바인딩된 이벤트 노드**이지, 외부에서 직접 호출 가능한 UFunction이 아니다(코디네이터 전제와 일치).

**하류 exec 체인 전체(핀 원문, 3노드로 완결)**:
```
K2Node_ComponentBoundEvent_0 .then
 → K2Node_MacroInstance_3 (Utilities|IsValid, InputObject=VariableGet_3.ManagerRef) .Is Valid
 → K2Node_CallFunction_17 (|NotifyAttackButtonClicked, self=VariableGet_3.ManagerRef) .then → [] (연결 없음, 체인 종단)
   (Is Not Valid 출력도 → [] 연결 없음)
```

`CallFunction_17`의 입력 핀은 `execute`·`self` **2개뿐** — 다른 파라미터 없음. 이는 호출 대상 함수 자체가 무인자임을 의미하며, `BP_BattleManager.NotifyAttackButtonClicked`의 `K2Node_FunctionEntry_0` 출력 핀도 `then` 1개뿐(입력 파라미터 pin 0개)으로 재확인했다.

**`NotifyAttackButtonClicked` 내부 — Start/Cancel/End 겸용 분기 조건**(전부 `BattleState`/`bInputLocked` 값 분기, 파라미터 없음):

```
FunctionEntry.then
→ IfThenElse_2  Condition = (BattleState == 0)         [PromotableOperator_2: A=GetBattleState, B=0]
    then → CallFunction_4 (|StartBattle)                 ← BattleState=0 일 때 "Start" 역할
    else → IfThenElse_3  Condition = (BattleState == 6)  [PromotableOperator_1: B=6]
        then → CallFunction_3 (|InitBattle)               ← BattleState=6 일 때 재초기화 역할
        else → IfThenElse_0  Condition = GetbInputLocked (raw bool, true=잠김)
            then(잠김)   → CallFunction_2 (PrintString "NotifyAttackButtonClicked: BLOCKED (bInputLocked=true)") → [] (무동작)
            else(안잠김) → IfThenElse_1  Condition = (BattleState == 2)  [PromotableOperator_0: B=2]
                then → [] (연결 없음, 무동작 — BattleState=2에서는 클릭 무시)
                else → CallFunction_1 (|EnterAwaitCommand)   ← 일반 "공격 선택 진행" 역할
```

**요약 답변**:
- 하류 exec 체인: 위 코드블록(완전 인용, 3+7노드).
- 호출하는 `BP_BattleManager` 함수: **`NotifyAttackButtonClicked`**(노드 `K2Node_CallFunction_17`).
- 파라미터 없이 호출 가능한가: **예.** `execute`+`self`만 요구하는 무인자 커스텀 함수.
- Start/Cancel/End 겸용 분기 조건: **`BattleState`(byte, 값 0/6/2/그외) + `bInputLocked`(bool)**. 클릭 이벤트 자체에는 모드 파라미터가 없고, 전부 `BP_BattleManager`가 자신의 현재 상태로 판단한다. `BattleState` enum의 각 값 라벨명(0="?", 2="?", 6="?")은 **미확인**(전용 Enum 애셋을 찾지 못함 — C++ 네이티브 enum으로 추정, 값만 확인).

→ 자동 시작 훅 설계 함의: `BeginPlay`에서 `BattleState==0`을 보장한 뒤 `BP_BattleManager::StartBattle`(또는 `NotifyAttackButtonClicked` 자체)을 **직접 호출**하면 클릭 시뮬레이션 없이 동일 효과를 낼 수 있다 — 두 함수 모두 무인자이고 이 조사에서 실행 가능성을 막는 추가 게이트를 발견하지 못했다(단, 실제 실행 가능 여부는 PIE 검증 필요 — 본 세션은 미실행).

## H27 정정문 초안 (20곳 교체용 1단락)

> **정정**: `BP_BattleManager`의 `EnterExecuting`에서 캐릭터가 걸어나가는 것은 `IsAttackFamily`가 아니라 **`Target` 문자열 3-way 분기**(`IfThenElse_3`→`_4`, `BP_BattleManager.EventGraph`) 때문이다 — `Target=="ALLY1"` 또는 `Target=="SELF"`인 두 예외만 `WalkForward`(self=`ActiveUnit`)를 건너뛰고, **그 외 모든 값**(`ENEMY1` 포함)은 `WalkForward`로 흐른다. `IsAttackFamily`(`BP_BattleSpawnPoint.EventGraph`의 `IfThenElse_10`, `F_MotionsRow.IsAttackFamily` 필드)는 이것과 **무관한 별개 게이트**로, 하류 소비 대상이 `CallFunction_117`(`SetWorldLocation`, self=**`EffectQuad`** 컴포넌트) 단 1개뿐이며 캐릭터가 아니라 **잔상(Smear) 쿼드의 무기추종 위치 재배치**만 통제한다. 즉 파이어볼이 걸어가서 때리는 것은 `AF=TRUE`가 아니라 `Target=ENEMY1`이 `ALLY1`/`SELF` 예외에 해당하지 않기 때문이다.

## 조사 중 발견한 다른 서술 오류 / 신규 이상 소견

1. **`IfThenElse_4.execute`의 고아 와이어** (§1 이상 소견) — `VariableSet_6`(`SetAttackPointOverride`, `GetArrayItem_0`/타깃 기반)의 `then`이 `IfThenElse_4.execute`로 연결돼 있으나 `VariableSet_6` 자신의 `execute`는 미연결. 기존 문서(`BP정리_통합명세` H02)는 `VariableSet_6`을 `IfThenElse_3`과 묶어 서술하는데, 실제로는 `IfThenElse_3`이 아니라 **`IfThenElse_4`**에 (죽은) 와이어를 대고 있다 — H02 서술을 "`IfThenElse_3.Condition` → (별개로) 고아 상태인 `VariableSet_6→IfThenElse_4` 와이어 존재"로 세분화할 필요가 있다. **수정은 하지 않았다.**
2. **노드 이름 재사용으로 인한 혼동 위험**: `K2Node_IfThenElse_10`이 `BP_BattleManager.ApplySkillEffects`(bAlive 게이트, `IsAttackFamily`와 무관)와 `BP_BattleSpawnPoint.EventGraph`(IsAttackFamily 게이트, §5)에 **동명이인**으로 존재한다. 향후 문서에서 그래프명을 반드시 함께 표기해야 한다(이번 §5에 명시함).
3. 그 외 명세-실측 불일치는 발견하지 못했다.
