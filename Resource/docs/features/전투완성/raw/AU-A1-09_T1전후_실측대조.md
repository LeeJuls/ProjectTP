## ① 실측 — 추론이 관측으로 승격됐다

**기존 판정의 한계**: [[턴길이_실측확정_2026-08-12]]는 T1 **이후** 세션 하나(07:32)만 갖고 *"T1은 턴 길이를 안 바꿨다"*를 **이론값**(`0.55+0.75+0.45=1.750`)과 대조해 판정했다. 맞는 결론이었지만 **T1 이전 실측이 없었다.**

**이제 대조쌍이 있다**:

| 세션(로컬) | T1 기준 | `ExecWalkPhase→TurnEnd` | `TurnEnd→TurnStart` |
|---|---|---|---|
| 08-11 21:14 | 이전 | 1.758 외 | 0.350 |
| 08-11 23:23 | 이전 | **1.750** ×6, 1.751, 1.759 | **0.350** ×8 |
| 08-11 23:53 | 이전 | **1.750** ×3 | **0.350** ×3 |
| 08-12 00:15 | 이전 | **1.750** ×2, 1.751 | **0.350** ×3 |
| 08-12 01:05 | 이전 | **1.750** ×2 | **0.350** ×2 |
| 08-12 01:08 | 이전 | **1.750** ×4 | **0.350** ×4 |
| ★**08-12 07:32** | **이후** | **1.750** ×5 | **0.350** ×5 |

**판정**: `ExecWalkPhase→TurnEnd` 고유값 — T1이전 `{1.750, 1.751, 1.758, 1.759}` / T1이후 `{1.750}`.
편차 최대 **0.009**는 60fps 프레임 양자화(`1/60 = 0.0167`) 이내다.

→ ★**T1은 턴 길이를 바꾸지 않았다. Δ = 0.000.** 이론 대조가 아니라 **실측 대 실측**으로 닫혔다.

**부수**: `TurnEnd→TurnStart`에 `0.016` 이상치 1건 — 전투 종료/재시작 경계로 추정. **미조사**(판정에 영향 없음).

## ★② 부산물 — UE 천 단위 쉼표. 하마터면 가짜 결함을 잡을 뻔했다

### 어떻게 드러났나

첫 분석에서 21:14 세션만 이질적이었다:

```
ExecWalkPhase→TurnEnd : [1.758, 0.026, 0.026, 0.026, ...]   ← ★0.026?
TurnEnd→TurnStart     : [0.35, 0.376, 0.376, 0.376, ...]
```

원문을 자르지 않고 보니:

```
State:TurnStart:t=6.376
State:AwaitTarget:t=6,915.2      ← ★★쉼표
State:TurnEnd:t=6,917.834
```

★**내 정규식 `[\d.]+`가 `6`에서 멈췄다.** `6,915.2`(6915.2초 = 1시간 55분 지점)를 `6`으로 읽어 델타가 전부 무너진 것이다.

★**하마터면**: 이걸 *"turn 2부터 타임스탬프가 `6`에 고정되는 로그 결함"*으로 기록할 뻔했다. **실재하지 않는 결함**이다 — 파서가 틀렸다.

### 규칙

```
State:AwaitTarget:t=6,915.2      ← float → ★쉼표 붙는다
FXLAB:FXNOROW:63009999           ← int   → 안 붙는다 (8자리인데도)
```

UE의 **float→string은 로케일 포맷**을 타고 **int→string은 안 탄다.** 둘이 **같은 로그에 공존**한다.

★**발현 조건이 고약하다** — 값이 **1000을 넘어야만** 나타난다. 짧은 세션에서는 영원히 안 보인다. *"지금까지 안 났으니 괜찮다"*가 근거가 되지 못한다.

### ★이건 `oracle_diff`의 실제 결함이었다

`rows_equal()`이 **문자열 비교**였다:

```python
all(str(a.get(c, "")) == str(b.get(c, "")) for c in ORACLE_COLUMNS)
```

→ 라이브 `dmg=1,234` vs 오라클 `1234`가 **불일치**로 잡힌다. ★**가짜 FAIL**이고, 그것도 *"오라클이 틀렸다"*로 오독되기 쉬운 모양이다.

**지금은 미발현**이다(실측 dmg 집합이 전부 세 자리). 그러나 **알파에서 HP·데미지가 커지는 순간** 조용히 나타나고, ★**S1 봉인 판정이 이 비교기에 걸려 있다.**

### 조치 4건

| # | 무엇 |
|---|---|
| 1 | `parser.normalize_number()` 신설 — 숫자로 해석되는 값만 쉼표 제거, `A3`·`false`·빈 문자열은 **원문 보존** |
| 2 | `oracle_diff.rows_equal()`이 비교 전에 이걸 거치도록 수정 |
| 3 | `전투로그.md` **§1-6** 신설 — 함정·규칙·위험 필드 명시 |
| 4 | `tokens.py` 순번17(`PlayAttack\|...\|t=`) note에 경고 — ★**아직 안 심었으므로 지금이 막을 마지막 시점** |

★**`dmg` RAW 계약(§1-4)과 충돌하지 않는다** — `parse_pipe_kv()`는 값을 원문 그대로 두고, **숫자로 해석하려는 소비자만** 정규화를 거친다. "원문 보존"과 "숫자 정규화"의 책임이 분리돼 있다.

**회귀 방지**: selftest에 2케이스 추가 — 정규화 자체 9건 + ★`rows_equal`이 **실제로 그 정규화를 거치는지**(헬퍼만 고치고 소비처를 안 고치는 실수 차단). **32/32 PASS**.

## ★교훈 — "이상한 값"을 결함으로 기록하기 전에 원문을 봐라

3fps 양자화 때도 같은 구조였다: **측정 아티팩트를 실체로 오독**할 뻔했다(H18 "0.58초 블록"). 이번엔 **파싱 아티팩트**였다.

공통점 — ★**둘 다 "값이 이상하다"에서 멈추지 않고 원문을 끝까지 보니 갈렸다.** 21:14 세션을 *"조건이 다른 세션"*으로 제외했으면 함정을 못 찾았고, `oracle_diff`는 **알파에서 터졌을 것**이다.
