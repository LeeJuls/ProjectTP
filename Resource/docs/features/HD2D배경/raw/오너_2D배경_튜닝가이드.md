# 오너용 — `map_battle_2d` 2D 배경 튜닝 가이드
#projectTP/HD2D배경

> 이 문서는 **에디터에서 직접 값을 바꿔볼 수 있게** 액터 이름·경로·현재값·조정 방향을 정리한 것이다. 미적 최종 판단(색조·밀도·구도)은 전부 오너 몫이며, 여기서는 "무엇을 어디서 바꾸면 뭐가 되는지"만 안내한다.

> 상위 지침: [[룩_지침_2D타일셋]] · 판정: [[목업_유효범위_판정]]

## 0. 지금 상태 요약

- `map_battle_octopath`를 복제해 만든 레벨. **배경(Village Pack 소품 315개)만 제거**하고 2D 타일셋 액터 11개로 교체했다.
- **캐릭터 8기(`BP_BattleSpawnPoint`)·카메라·라이팅·PPV·BattleManager·UI 버튼은 전혀 건드리지 않았다.**
- **`Tint`는 흰색(무보정), `TilingScale`은 1.0(기본값)** 그대로 — 원본 색으로 먼저 띄운 상태다. 어젯밤 캘리브레이션에서 오프라인 톤다운 수치가 엔진과 5~9배 어긋남을 실측했으므로([[목업_유효범위_판정]]), **여기서부터 눈으로 보고 조정 시작**.
- DoF는 켜지 않았다(옥토패스대치 S3 기존 결정 유지).
- PIE는 실행하지 않았다(Non-goal) — 아래 ⑨ 알려진 이슈는 전부 에디터 뷰포트 좌표 실측 기반이며, 실제 플레이 화면에서 재확인 필요.

### ★Director 사후 수정 2건 (2026-08-10, scene-builder 보고 후)

배치 직후 Director 실측에서 **오너 육안 평가를 막는 결함 2건**을 발견해 즉시 고쳤다. 둘 다 되돌리기 쉬운 값 변경이다.

## ① 지면 밝기·색조 — ★가장 먼저 만질 것

| 항목 | 위치 |
|---|---|
| 애셋 | `/Game/Materials/Tileset/MI_Ground_Grass` (콘텐츠 브라우저에서 더블클릭 → Details 패널) |
| 액터 | 아웃라이너 `Background2D/Ground/BG2D_Ground_Main` (레벨에 배치된 실제 바닥 평면) |
| 파라미터 | `Tint` (벡터/색상) |
| 현재값 | `(1, 1, 1, 1)` = 흰색 = 무보정 (텍스처 원본 그대로) |

**조정 방향**: 텍스처가 원본이라 실제로 밝게 나올 가능성이 높다. 어둡게 하려면 `Tint`의 RGB를 **1보다 작은 값으로 동시에 낮춘다**(예: 0.5~0.6이면 절반 밝기, 회색조가 아니라 특정 색을 강조하려면 R/G/B를 다르게 — 예를 들어 초록을 살리고 싶으면 G만 덜 낮춘다). 알파(A)는 보통 1 유지.
**참고**: 이 값은 `MI_Ground_Grass` 하나만 바꾸면 되지만, 다른 지면 배리에이션(`MI_Ground_Dirt`)도 있다 — 그늘진 구역이나 클래시 존(양 진영이 맞붙는 중앙)에 다른 톤을 쓰고 싶으면 `Ground_Main` 옆에 별도 평면을 추가하거나 `Ground_Main`의 머티리얼을 교체하면 된다.

## ② 타일 반복 밀도

| 항목 | 위치 |
|---|---|
| 애셋 | `/Game/Materials/Tileset/MI_Ground_Grass` (그리고 벽 계열 `MI_Tile_WallStone`/`MI_Tile_WallMerlon`도 동일 파라미터 보유) |
| 파라미터 | `TilingScale` (스칼라) |
| 현재값 | `1.0` (48px 타일 = 월드 155.5cm 캘리브레이션이 이미 반영된 기본값) |

**조정 방향**: 값을 **올리면** 타일이 더 작게/촘촘하게 반복된다(같은 면적에 타일이 더 많이 보임). **내리면** 타일이 더 크게 늘어나 반복 횟수가 줄어든다(단, 텍스처가 흐릿해 보일 수 있음). 기본값 1.0이 캘리브레이션 기준이므로, 반복 패턴이 눈에 띄게 거슬릴 때만 미세 조정 권장(예: 0.8~1.3 범위에서 시작).

## ③ 벽 위치 — 원경감 조정

| 액터(아웃라이너) | 애셋/머티리얼 | 현재 Location | 현재 Scale |
|---|---|---|---|
| `Background2D/Wall/BG2D_Wall_Body` | `SM_SpriteQuad` + `MI_Tile_WallStone` | X=0, Y=-5650, Z=805 | X=40(폭4000), Y=3.5(높이350), Z=1 |
| `Background2D/Wall/BG2D_Wall_Merlon` | `SM_SpriteQuad` + `MI_Tile_WallMerlon` | X=0, Y=-5650, Z=1030 | X=40(폭4000), Y=1(높이100), Z=1 |

**좌표계 참고**: 이 무대는 카메라가 Y=-8730 부근에서 **+Y 방향을 바라본다**. 즉 **Y값이 클수록(덜 음수일수록) 카메라에서 멀어지는 "원경" 방향**이다.
- **더 원경으로 보내려면**: Y를 더 크게(예: -5650 → -5400). 화면에서 작아지고 흐릿한 인상.
- **더 낮게(덜 위압적으로) 하려면**: `BG2D_Wall_Body`의 Scale.Y(높이 배율)를 줄인다 — 목업 v1이 "벽이 화면 60% 점유"로 실패했던 지점이라 현재 350cm 높이로 낮게 시작했다. 더 낮추려면 Scale.Y를 3.5→2.5~3.0 사이로.
- Location.Z는 바닥(Z=630)에서 벽 높이의 절반만큼 위로 띄운 값이라, Scale.Y를 바꾸면 **Location.Z도 같이 재계산**해야 발이 땅에 붙는다: `Location.Z = 630 + (Scale.Y × 100) / 2`.

## ⑦ ★카메라 — 진형폭 대 화면폭

| 항목 | 값 |
|---|---|
| 액터 | 아웃라이너 `BattleStage/Camera/BattleCamera` (`CameraActor_0`) — **미변경, 참고용** |
| Location | (-170.58, -8730.78, 1207.07) |
| Rotation | Pitch=-6, Yaw=84, Roll=0 |
| FOV (`CameraComponent`) | 90° |
| AspectRatio | 1.778 (16:9) |

**실측 결과(이번 작업에서 확인)**: 이 카메라 그대로 `WorldPosToScreenCoords`로 진형 좌우 끝(Party A1 / Enemy B2)을 재보니 **화면폭의 약 65%를 진형이 차지**했다(화면 X 0.225~0.877). 어젯밤 오프라인 목업이 우려했던 "38%밖에 안 됨" 문제는 **실제 엔진 카메라에서는 재현되지 않았다** — 이건 오프라인 목업이 실제 원근/FOV를 정확히 반영하지 못했기 때문으로 보인다. 즉 **카메라값 자체는 지금 그대로 써도 진형이 화면을 충분히 채운다.**

더 좁게/넓게 조정하고 싶다면:
- **FOV를 낮추면**(예: 90→70) 화면이 좁아져 진형이 화면에서 차지하는 비율이 커진다(망원 효과, 배경도 확대되어 보임).
- **카메라를 더 뒤로(Y를 더 음수로, 예: -8730→-9200) 물리면** 진형 비율이 작아지고 배경이 더 많이 보인다.
- **좌우 반전 주의**: 이 카메라는 Yaw=84(90에 가깝지만 정확히 90은 아님)라, 월드 X가 **음수일수록 화면 오른쪽, 양수일수록 화면 왼쪽**으로 매핑된다(실측 확인). Party(A1~A4, X 음수)가 화면 오른쪽, Enemy(B1~B4, X 양수)가 화면 왼쪽에 나타난다는 뜻이다 — 이건 기존 카메라 설정을 그대로 쓴 결과이며 이번 작업에서 새로 만든 특성이 아니다. 좌우를 바꾸고 싶다면 카메라 Yaw나 위치를 조정해야 하는데, 이는 카메라 담당(scene-builder 재작업 또는 hd2d-art-director) 영역이라 오너 판단 후 별도 요청 필요.

## ⑨ ⚠ 알려진 이슈 — Director/오너 판단 필요

### (a) 원본 3D 지형(Landscape)이 새 평면 바닥을 뚫고 나올 위험
지시서가 "Village Pack 배경 액터만 제거"로 범위를 못박아서, **`environment/day/Landscape_1`(원본 3D 지형)은 건드리지 않았다.** 그런데 이 지형은 굴곡이 커서(실측 Z 446~820+), 새로 깐 평면 바닥(Z=630)보다 **더 높이 솟은 지점이 존재**한다:

|---|---|---|---|

### (b) 캐릭터 발밑 높이 불일치
새 바닥 Z=630은 지형이 아니라 `BP_BattleManager`(Z=630)·`BP_AttackPoint`(Z=640.4) — 즉 원래 지형과 무관하게 설계자가 잡아둔 "명목상 전투 바닥" 값을 기준으로 정했다(캐릭터 8기는 각자 지형에 스냅된 서로 다른 Z를 갖고 있어 하나의 평면으로 전부 맞출 수 없음). 대부분은 ±55 이내로 큰 위화감이 없을 것으로 예상되지만, 아래 2기는 특히 주의:

### (c) UI 버튼 가려짐 가능성
`BattleStage/UI/UI_CamToggle`, `UI_AttackButton`(둘 다 Z=420)은 새 바닥(Z=630)보다 낮은 위치에 있다. 이 버튼들이 어떤 머티리얼로 렌더링되는지에 따라 새 바닥에 가려 안 보이거나 클릭 안 될 수 있다 — **PIE에서 verifier가 반드시 확인 권장.** (참고: 이 문제는 원본 지형에서도 이미 존재했을 가능성이 있다 — 위 (a) 표에서 UI_AttackButton 근처 지형이 이미 Z=820으로 버튼보다 훨씬 높았다.)
