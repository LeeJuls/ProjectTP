# UE 5.8 Codex 학습·적용 계획

> 상위: [[projectTP_허브]] · 기록 대상: [[codex/UE5.8_projectTP]] · 기존 근거: [[언리얼5.8_기술카탈로그]]

## 목적

UE 5.8 공식 문서를 프로젝트에 필요한 범위에서 근거화하고, 그 결과를 별도 노트 [[codex/UE5.8_projectTP]]로 유지한다. 엔진 전체를 요약하거나 기존 카탈로그를 중복하지 않는다.

## 범위와 비범위

- 범위: 현재 A1 전투완성과 알파 루프에 닿는 Blueprint, UMG, DataTable/CSV, HD-2D 렌더링, 에디터 MCP·자동화, 테스트·패키징 준비.
- 다음 단계 후보: Enhanced Input/Common UI, Steam/EOS, 리플리케이션, GAS/C++ 코어 이관.
- 비범위: 현 단계와 접점이 없는 대규모 월드·MetaHuman·PCG·XR·Lumen/Nanite/MegaLights의 재조사. 채택 여부는 [[언리얼5.8_기술카탈로그]]의 결론을 따른다.

## 단계와 게이트

### S1. 기존 결정과 공식 문서 근거 정합성 확인

- 기술 카탈로그의 `지금 쓸 것`, `미확인`, `무관` 분류를 현재 A1·알파 문서와 대조한다.
- 산출물: 필요한 기능·채택 시점·금지/보류 근거 목록.
- [S1][TC-01] 모든 현재 우선 기능에 공식 UE 5.8 문서 링크와 적용 시점이 있다 → 누락 0건 | PASS
- [S1][TC-02] 미확인 사항이 확정 사실로 기록되지 않는다 → 미확인 표기 유지 | PASS

### S2. 프로젝트 기능 매핑

- 드래프트→4:4 전투→결과 알파 루프를 기능 단위로 분해하고 엔진 책임을 매핑한다.
- 산출물: C++/Blueprint/UMG/에디터 자동화 책임 분리와 검증 우선순위.
- [S2][TC-01] 모든 알파 핵심 기능에 구현 책임과 테스트 게이트가 있다 → 누락 0건 | PASS

### S3. 독립 `codex` 기록

- `docs/codex/UE5.8_projectTP.md`에 현재 적용 기술, 후속 검토 트리거, 작업 규칙, 문서 링크를 기록한다.
- [[개발_워크플로우]]의 기존 5단계 게이트·역할·TC 표기 규칙은 변경하지 않는다.
- [S3][TC-01] `codex`가 기존 워크플로우와 모순되지 않는다 → 5단계/TC 규칙 보존 | PASS
- [S3][TC-02] 모든 새 링크가 vault 안에서 해석되거나 공식 문서 URL이다 → 깨진 링크 0건 | PASS

### S4. 이후 기능 작업에서의 갱신

- 기능 청사진/plan 작성 시 review의 해당 항목을 참조하고, 새 사실은 근거 링크·검증 결과와 함께 갱신한다.
- [S4][TC-01] 새 엔진 기능 채택은 문서 근거·채택 이유·검증 TC를 함께 남긴다 → 세 항목 충족 | 대기

## 승인 요청

S1~S3을 실행해 `docs/codex/UE5.8_projectTP.md`를 만들기 전, 본 계획의 범위와 게이트를 승인받는다.
