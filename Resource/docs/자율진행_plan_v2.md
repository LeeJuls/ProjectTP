## 2. ★무거운 판정 3가지

### (가) SCF + 트리거 벽 → **FT1 "검증 하네스" 신설**

★**둘은 같은 문제의 두 얼굴**이다 — F트랙의 실증 TC 전부가 *"PIE에서 임의 발화"*를 요구하는데 **그 수단이 없다.** 개별 우회 대신 한 단계로 묶는다.

**FT1 = MA 훅(1a) + 자동 시작 토글(1b) + SCF 호출기(1c)**. 셋 다 `BP_BattleManager` 계열 **additive 스캐폴드**로 성격이 같다.
- **커밋·세이브포인트는 3분리**(롤백 경계 원칙), 게이트는 FT1 하나
- ★**자동 시작 토글을 F트랙 필수로 승격** — 없으면 FT2~FT8의 모든 실증이 **케이스마다 오너 클릭 1회**에 걸려 세션 경제가 붕괴한다. *"막힌 지점이 정확히 1개"*라는 A1 실측이 이 투자의 근거

## 8. ★AT트랙 세부 v2 추가 확정사항 (2026-08-12)

### 8-1. ★FX 예산 확정 — `SlotBudgetSec`는 2.1이 아니라 **1.200**

턴 내부를 핀 원문 실측으로 쪼개면:

| 구간 | 길이 | FX 가용 |
|---|---|---|
| 전진 + `Delay(0.55)` | 0.550 | ✗ (`PlayAttack`이 0.550에 호출) |
| ATTACK1 `Delay(0.75)` | 0.750 | ✓ |
| 복귀 `Delay(0.45)` | 0.450 | ✓ |
| 턴 간극 `Delay(0.35)` | 0.350 | ✗ |

★`2.100 − 0.550(전진+Delay) − 0.350(턴 간극) = **1.200`**. 2.1을 상한으로 쓰면 **0.9초 과대 배정**이 된다. `Delay(0.55)`는 **3경로 합류 노드**라 전진을 스킵해도(막기·치유·원거리 포함) 항상 소비된다.

**귀결 2건**:
- ★`D5 §7-5`의 *"FPS 10 → 20"* 권고는 **stale** — FPS 20에서도 창을 0.65초 초과한다. 순차 배선이면 FPS 40, 임팩트 병렬이면 24 필요
- ★`D1 §9-3` 가산식이 실측과 정확히 0.55 어긋난다(임팩트 FX는 병렬이라 턴에 0을 더하는데 식은 0.55를 더함) → `L27` 린트를 그대로 돌리면 멀쩡히 도는 라이브 기본공격이 FAIL(2.30 > 2.1). **AT6/D6 전 식 정정 필요**

**노브 상한**: `SlotBudgetSec` **1.200**(하드) · `VfxFps` 하한 **24**(20 이하는 창 초과) · `FxSafetyMarginSec` **0.05**(고정) · 가짜 블로킹 기본값 ★**0**(H18 블록 부재 확정 → 기존 "0.58로 초기화" 권고는 폐기).
