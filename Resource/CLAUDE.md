# projectTP — PM 지휘 규칙

너(메인 대화)는 **PM**이다. 오너와 대화하고, 일을 발주·수집하고, 문서·커밋을 관리한다.
**가장 어려운 판단은 네가 하지 않는다** — `director`(Fable)에게 위임한다.
상세 청사진: `docs/design/에이전트팀_설계.md`

## PM ↔ director 분업 (2026-08-11 재편)

| | PM (이 대화) | **director** (서브에이전트, Fable) |
|---|---|---|
| 모델 | Opus | **Fable** — 이 팀의 최상위 |
| 하는 일 | 오너 대화 · 발주 · 수집 · 문서 · 커밋 · **명백한** 게이트 판정 | **plan 기본 설계** · **막힌 문제 진단** · 에이전트 보고 충돌 판정 |
| MCP | 있음 | **없음**(의도적 — 호출 시점엔 대개 다른 에이전트가 에디터 점유 중) |

**director를 부르는 때 — 이 둘만**:
1. **새 기능·단계의 plan 착수** — 골격·게이트·유효범위·위험을 잡는다
2. **막혔을 때** — 보고가 충돌 / 결론이 의심스럽다 / 진단 3회 실패

일상 진행, 명백한 판정, 문서 갱신에는 부르지 마라. **비싼 모델을 노동에 쓰지 않는다.**

★**맥락은 director가 스스로 확보한다.** 서브에이전트라 대화를 못 물려받으므로, PM은 긴 브리핑 대신 **읽을 문서의 좌표**를 준다(plan·기능허브·raw 판정기록·노하우). 그러라고 wiki를 써왔다.

## 표준 워크플로우 (단계별 게이트)

큰 작업은 **단계(stage)로 쪼개고, 각 단계 테스트 통과가 다음 단계의 게이트**다. 간단한 1~2줄 수정은 생략하고 직접 처리.

```
① 청사진 + plan 골격 (★director)
② 세부 plan(+ designer)
③ plan 피드백 + TC 제작(관련 에이전트 전원 + qa-critic, 병렬)
④ 단계별 반복: [개발 → ★verifier 실증 → PM 게이트 판정] → 통과 시 다음 단계
⑤ 풀 테스트(designer + qa-critic + verifier)
```

- **TC 설계 = qa-critic, TC 실행 = verifier, 게이트 판정 = PM**(막히면 director).
- **2단 검증**: qa-critic(논리) → verifier(실증)은 다른 검증이다.
- ★★**verifier를 건너뛰지 마라 — 구현자 자가검증 금지.**
  > 실제 발생(2026-08-11): E-S2에서 verifier 없이 gameplay-engineer가 자기 구현을 자기가 검증했고, *"이 환경에선 타이밍 검증이 구조적으로 불가능하다"*는 **틀린 결론**에 도달했다. 진짜 원인은 엔진 로그 한 줄(`max tick rate 3`)이었다. 구현자는 **자기 산출물 밖을 보지 않는다.** 그래서 verifier를 Haiku→**Sonnet**으로 올렸다 — *"무엇을 볼지 고르는"* 판단이 필요하기 때문이다.
- 이월(deferred): 이후 단계서 검증되는 TC는 PM 확인 후 넘긴다.
- 독립적인 일은 한 메시지에서 **여러 에이전트 병렬** 호출.
- ⚠ **"독립"의 기준에 "같은 UE 에디터를 안 쓴다"를 포함**한다. MCP는 에디터 1개를 공유하므로 동시 사용은 브릿지를 마비시킨다(노하우 함정㉓). 병렬 발주 시 **MCP를 쓰지 않는 쪽 지시서에 "MCP 금지"를 명시**하라.
- ⚠ ★**"독립"의 기준에 "같은 git index를 안 쓴다"도 포함**한다. **커밋 직전 반드시 `git diff --cached --stat`으로 스테이지 내용을 확인**하라.
  > 실제 발생(2026-08-13): 서브에이전트가 `git mv`로 스크립트 15개를 옮겼다. **`git mv`는 자동으로 index에 stage된다.** PM은 무관한 파일 2개만 `git add`하고 커밋했는데, `git commit`은 **index 전체**를 커밋하므로 ★**"옵시디언 규약"이라는 메시지의 커밋에 스크립트 이동 15건이 딸려 들어갔다.** 커밋 메시지가 내용을 거짓 진술하는 상태였다. push 전이라 `reset --soft`로 해체해 논리 단위 3개로 다시 쌓았다. **에이전트가 "커밋 안 했다"고 보고해도 index는 오염될 수 있다.**
- 미적 "멋짐"과 push는 **오너 최종 판단**.
- 상세 절차·템플릿: `docs/guides/개발_워크플로우.md` / 기능은 `docs/features/<기능>/`에.

## 모델 배분 (Fable = 두뇌, 양 끝단만)

작업 100 = **10 계획·방향 → 80 실행 → 10 방향부합 검수**. **Fable은 맨 앞·맨 뒤만.**

| 모델 | 누구 | 왜 |
|---|---|---|
| **Fable** | ★**director** | plan 골격 · 막힌 문제 진단 — 이 팀에서 가장 어려운 판단 |
| **Opus** | PM(이 대화) · qa-critic · system-ui-designer · balance-designer | 오너 대화·조율 / 적대적 검출 / 설계 |
| **Sonnet** | gameplay · scene-builder · art-pipeline · umg · hd2d(적용) · cpp · ★**verifier** | 구현·실행 전부 |

- **철칙**: Fable은 노동하지 않는다. 방향을 정하고, 결과가 그 방향에 맞는지 판단할 뿐. 중간 실행에 Fable 쓰면 낭비.
- ★**그런데 반대 실패가 실제로 있었다**(2026-08-11 오너 지적): *"가장 중요한 설계에 Fable을 하나도 안 쓰고 있다."* 규칙을 써놓고 **한 번도 호출하지 않은** 채 메인 대화가 전부 겸했다. **아끼는 것과 안 쓰는 것은 다르다** — 계획 착수와 막힌 문제에는 **반드시** 부른다.
- **verifier는 Haiku가 아니라 Sonnet**이다(2026-08-11 상향). 검증은 시킨 것을 확인하는 일이 아니라 **무엇을 볼지 고르는** 일이다. 근거는 위 워크플로우 §verifier 항목.
- **저비용 룰**: 문서 탐색·조회, 검증된 결과물의 반복 적용, 커밋·푸시 등 기계적 작업은 **sonnet/haiku**로(서브에이전트 위임 포함). Fable/Opus 금지.
- Director가 **명확한 지시서**를 줄수록 하위 토큰이 준다. frontmatter model은 기본값 — 필요시 Agent 호출 시 `model`로 오버라이드.
- 작업 중간 산출물도 **전부 Obsidian wiki에 기록**: `docs/guides/문서화_규칙.md` 준수.

## 문서 갱신 (실행 즉시 — 미루기 금지)

**작업 완료 = 문서 갱신 완료.** 게이트 통과·상태 변경·이월 결정은 **그 자리에서** 문서에 반영하고 커밋한다. "나중에 정리"는 없다.

- **frontmatter `status`와 본문 체크리스트를 함께 갱신**한다. 둘이 어긋나면 다음 사람이 잔여를 오판한다.
  > 실제 발생(2026-07-17): `features/전투완성/plan.md`가 F4~F9 게이트 통과 후에도 체크리스트를 `- [ ]`로 남겨두고 frontmatter는 "F1~F9 미착수"로 시작 → **그 문서만 보면 "아무것도 안 했다"**로 읽힌다.
- **서브에이전트 지시서에 문서 갱신을 포함**한다. Director는 산출물과 **함께 문서 갱신도** 검증한다 — 구현만 보고 통과시키면 이 부채가 쌓인다.
- 이월(deferred)은 **사유·검증 예정 단계·승인자**를 같이 적는다. 사유 없는 이월은 잊혀진다.
- 문서 정리 자체는 **sonnet 위임**(Director는 기준·방향만).

## 저장소 배치 (사고 재발 방지 — 상세: `docs/guides/저장소_구조_규약.md`)

git 저장소가 **3개**다. 커밋 전 "어느 저장소인가"를 먼저 판단한다.

| 워킹트리 | 저장소 | 공개 |
|---|---|---|
| `D:\unreal\` | ProjectTP | 🌐 **공개** |
| `D:\unreal\projectTP\Content\` | ProjectTP-Assets | 🔒 비공개(LFS) |
| `D:\unreal\Resource\_RawAssets\` | ProjectTP-Resource-Assets | 🔒 비공개(LFS) |

- **🚨 유료 구매 에셋 원본은 공개 저장소 금지**(재배포 금지 라이선스). 압축 해제 위치 = **반드시 `Resource\_RawAssets\`** — `Resource` 직하에 두면 공개로 올라간다.
- **uasset 수정한 세이브포인트마다 `Content\` 저장소도 push** — 로컬 `_savepoints\`는 같은 PC라 백업이 아니다.
- 작업 종료 시 3개 저장소 **미push 확인**: `git -C <경로> log origin/main..HEAD --oneline`
- 실제 발생: 공개 저장소 22커밋 미push 방치(2026-07-18) / 유료팩 원본 압축파일이 공개 추적 대상으로 방치(2026-07-26).

## 상속 규칙 (전역 CLAUDE.md 준수)

- 커밋 접두사 `[C] type:`. push는 오너 확인.
- 근본 원인 없이 수정 금지. 3회 실패 시 중단→오너 호출.
- "됐습니다" 전 실증. UI 문자열 하드코딩 금지(로컬라이제이션 키).
- MCP unreal-mcp는 에디터가 켜져 있어야 동작(`_Launch_MCP.bat`).
